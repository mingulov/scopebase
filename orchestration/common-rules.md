# ScopeBase worker rules

Read root AGENTS, the selected task brief, its specification and the user goal snapshot. The specification controls behavior; a plan or test that contradicts it needs a controller ruling. Keep model/effort, base commit, allowed paths and resource ownership from the brief explicit.

- Work only in the assigned registered worktree on its recorded branch. Do not spawn workers/reviewers, ask the user directly, alter the controller ledger, mark product tasks accepted, merge, push, publish or change global configuration. Return NEEDS_CONTEXT to the controller for a genuine missing decision while continuing independent work when possible.
- Preserve the hard-won donor implementations and tests. Inspect selected branches/worktrees and applicable WIP read-only; pin copied/adapted bytes and licensing. Port the bug fix and its regression together. Improve architecture/API when justified, with a source-to-contract map and new tests for changed edges. Record new necessary work in the task report for controller TODO integration.
- A job with suspended writing permission retains every path/resource claim but must not edit source, start further job builds/tests or resume a worker. Only a confirmed durable `resume-writing` grant followed by a new explicit controller assignment referencing that grant permits further writing; an old immutable brief/dispatch is insufficient. `PREPARED`, launch text, PID absence and acceptance do not prove quiescence. Preserve partial writing state and stop for controller review; never repair/delete/replay it automatically.
- Respect exclusive file ownership. Root Cargo/lock, exports, shared schemas/profile indexes and documentation ledgers have one integration owner. Report an unexpected dirty or out-of-scope path; preserve it. Do not stash, reset, clean, switch, rebase, amend earlier commits or delete branches/worktrees.
- Use the existing authorized Git identity; do not invent an author, impersonate another agent or add a blanket attribution policy from another project. Commit only the owned deliverable. Inspect author/committer and exact range before handing off.
- For behavior changes, demonstrate the original regression or intended failing control before the fix, then preserve its successful twin. Expected truth comes from an independent fixture/workload/oracle. A setup failure, missing positive population or dependency self-copy cannot prove the semantic assertion. Test every affected site and consumer.
- Never weaken an existing expectation merely to get green. A legitimate assertion/fixture/contract change needs a recorded controller ruling, explanation and compensating regression. Do not add hidden skips, failure suppression, stale binary fallback or retries that erase a semantic failure.
- Run focused tests plus the normal applicable package suite and causally affected downstream/object/live checks. Distinguish source inspection, models, real host, final emitted objects, live kernels and installed clients. Missing required environment/results remain OPEN/INCOMPLETE. No compile/load/quiet-poll/exit-zero result alone proves BPF semantics or cleanup.
- CI/CD and privileged tests are authorized when required by the active goal. Use explicitly owned resources and current leases; never signal a guessed PID, delete an unproven path or change host policy to force a pass. Preserve unresolved work/map/link/child/output custody through cancellation and failure.
- Use a private TMPDIR, CARGO_TARGET_DIR and evidence root from the brief. Heavy builds use the shared ScopeBase build lock. Paths are data: quote them and keep commands/arguments structured. Do not leak raw captured bytes, addresses, secrets or entire model transcripts into tracked/public artifacts.
- Write the requested report with status DONE/DONE_WITH_CONCERNS/BLOCKED/NEEDS_CONTEXT, full commits, exact commands/results, red/control evidence, decisions, assertion changes, concerns and resource disposition. These are worker statuses, not controller acceptance. Return a short summary and report path.

Readonly reviewer roles make no code, test, Git, environment or remote changes. Review the exact candidate and the tests' truth/non-vacuity. Muse findings are supplementary hypotheses for Sol/Astra/controller adjudication; Muse never replaces a required critical review.
