# Scoped generations and bounded history preservation

CP05 candidate mechanism/preservation record; acceptance and archive qualification are root-owned, separate evidence gates. No donor test result or source grant is presented as a ScopeBase runtime result.
A destroy or configuration operation submitted for one lifetime can return after the same raw address belongs to a new lifetime. Matching only the return-time raw value, retaining a shifting storage index, or promoting an unbound submission attributes the old operation to the newcomer. Evicting a tombstone also removes evidence: it cannot prove that an object never existed or that reuse is continuous. The production `generation::ObjectKey<K>` relation retains the complete caller epoch, generation and raw identity, compares metadata before one caller equality, and refuses overflow before one successful caller clone. It creates no identity or lifecycle policy.

The separate test-local `KModel` preserves submitted stable IDs, first-entry retention on duplicate tokens, separate pending/live/retired count bounds, forced ambiguous retirement and retired-only oldest-assignment eviction. `Mappings` preserves its separate retired ring and sticky uncertainty; `Reader` inserts only known identities into duplicate tracking. K `config_revision` is not capture Epoch. `allocate(raw, false)` consumes externally scripted missing-creation evidence, counted once at admission: it is not a port of K's ungranted first-seen/configuration branches.
