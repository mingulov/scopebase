# Issue and preserved-regression template

Reusable instructions for [preserved issue knowledge](README.md). Replace each instruction with concrete evidence or an honest unresolved reason/owner/exit criterion. No donor tests or implementation results are asserted here.

## Status and scope

State inspected, proposed, implemented, executed and unknown facts separately. Name affected capability/requirements/task and completion level. For unresolved content use UNKNOWN — reason; owner; exit criterion. A structural pass never means adoption or readiness.

## Trigger and invariant

Describe the minimized trigger, original defect, affected population and invariant in observable terms. Include cross-donor differences and application-local policies that must stay distinct.

## Selected source and license

Record completed private snapshot/history mapping, donor repository/full commit, selected file/symbol, WIP/dirty hashes and actual per-file source notices. Separate historical grant, author-authorized destination and host/BPF/shared/build roles. Preserve third-party terms; unresolved options stay explicit.

## Mechanism and destination

Map selected PORT/ADAPT symbols and all affected call sites to concrete destination behavior/API. NEW requires the packet-approved missing-mechanism reason/design; do not substitute a shorter rewrite or placeholder export.

## Original regression

Identify original test path/symbol/case and hard-won edge cases, source pin and inspected-versus-executed tier. Preserve all affected regressions alongside the mechanism.

## Independent oracle

Name independent expected literals/workload/model and how actual trigger/population is proved. Production resolver/serializer/adapter output cannot be its own oracle.

## Known-bad control and positive twin

Name a plausible semantic mutation/countermodel and intended failing assertion after valid setup, plus passing positive twin. A setup crash, dependency error or empty population is not a sensitive control.

## Contract references

Fill the single scopebase-doc block with a unique issue id, actual task/requirements, exact version domains, source-checked category pairs and planned base profiles. Case/fixture revisions belong to the actual artifact. No supported/qualified or executed claim fits this foundation format.

## Effects bounds and cleanup

Separate byte/work/memory/wait/resource bounds, incurred charges, partial observations and remaining owners. State cooperative timeout and ambiguous retry limits, retained original authority, fallible cleanup and explicit unresolved custody.

## Required environment and bindings

Name preselected required T0–T5 cases/cells, exact consumer/library/version/features/backend/compiler/object/profile/fixture/oracle bindings, independent positive/excluded populations and resource ownership. Required missing fixtures/activity/cleanup remain incomplete.

## Reference consumers and delivery

Name real differently wired public-path consumers, package-relative fixtures/developer conformance API and installed operator route over distributed bytes. NOT_IMPLEMENTED items need owner and exit criterion; ordinary downstream cargo test does not execute dependency tests.

## Upstream inclusion and removal test

Record actual known upstream issue/fix, selected dependency/compiler/backend inclusion evidence and removal test. Unknown issue numbers stay unknown. A merge or version comparison alone never permits removing a workaround; test the actual selected compiler/backend/object.

## Migration and duplicate retirement

State eventual migration/rollback/duplicate-retirement criteria and affected products. Package-ready and product-migrated are distinct; MG01–MG05 and external publication remain later. Report newly necessary work to the controller for TODO/dependency/exit-criterion integration.
