## Required issue record

Before promoting a mechanism, its concrete issue document includes the original defect and affected contract; donor repository/full commit/file and dirty hashes; license and destination provenance; a minimized reproducer with the actual trigger; independently generated expected evidence; a known-bad control that fails the intended semantic assertion; case/profile/requirement/task IDs; resource/effect/cleanup limits; required environment and final object/consumer binding; real reference consumers; and the later migration/duplicate-retirement criterion. Report inspected, proposed, executed and unknown information separately.

For a dependency/compiler workaround, also name the upstream issue/fix when known, selected consumer/compiler/backend versions and inclusion evidence, and the test that allows removal. An upstream merge or same-engine round trip is insufficient. Unknown external issue numbers stay explicitly unknown; SB01 does not invent them. Source symbols remain discoverable even when an API improves.

Run the affected tests after changing implementation, fixture, oracle, source selection, compiler or dependency bytes. Fix a sensitivity gap with a discriminating control; repeated stress without an oracle does not close it. Fixtures and a developer conformance API ship with the package, plus at least one independently usable installed operator route. Package users cannot rely on dependency tests running automatically.
