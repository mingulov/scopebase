## Explicit acquisition, approval and transformation policy

A feature-policy member may declare `minimal_dependencies`, an exact list of
dependency records drawn unchanged from its existing `allowed_dependencies`.
For every configuration whose selected subject features equal that member's
minimal features, the observed registry dependency name/version/source set must
match this list exactly. Missing or extra packages and changed versions/sources
refuse; an empty list requires no registry dependencies. Source digests, build
approvals, notices and denied-package checks still apply through ordinary
admission. This supports a parser with mandatory Serde without inventing an
optional feature. Members omitting the field retain the original empty-feature
Serde leakage guard. The explicit list is a reviewed policy input, never
generated from the observed Cargo result to make a failing check pass.

The Python 3.11+ standard-library tools have the bounded interfaces:

```sh
python3 tools/build/dependency_probe.py --matrix MATRIX --output-dir ABSOLUTE_NEW_DIR --report ABSOLUTE_NEW_REPORT
python3 tools/build/check_features.py --manifest Cargo.toml --matrix tests/package-policy/matrix.json --output-dir ABSOLUTE_NEW_DIR --report ABSOLUTE_NEW_REPORT
```

Run Cargo-producing commands through `bin/scopebase-build -- ...`. Each run owns its output, Cargo home, temporary directory and targets. Existing outputs/reports, source containment, symlink escapes, unknown/duplicate JSON fields and unexpected ancestor Cargo configuration refuse. Compiler environments are reconstructed; ambient flags, wrappers, runners, linkers and Cargo homes do not pass through. This is source admission, not a sandbox against malicious approved code.

Acquisition is separate: pinned Cargo 1.88 generates locks, explicitly fetches the selected closure and vendors offline with `--locked --offline --versioned-dirs`. Execution verifies/copies frozen archives, locks, standard checksum maps, complete vendor trees and retained license material into fresh outputs, then stays offline. It never generates Cargo checksum maps, copies a global cache, learns approvals or downloads during builds. Each matrix hashes its exact immutable inventory. The fixture matrix deliberately points to this task's retained private acquisition; another environment must prepare/select a new immutable inventory explicitly.

Only named per-case/member allowlists and top-level build/proc-macro approvals grant execution permission. Conservative resolved target/dependency kinds remain visible, including inactive-target over-approximation. Unknown ordinary scripts stay BLOCKED/APPROVAL_REQUIRED; forbidden native/BPF requirements refuse. The exact BTF URL/full-revision mapping and btf-rs → derive edge are acquired-probe exceptions, never permission for product sibling/donor paths.

Original local approval retains its complete regular-file inventory and whole-source digest. Copy verification preserves every original byte. A generated lock has a separate recorded identity; an existing original lock is retained and cannot silently change. Archive verification checks the actual package, exact delivered list, Cargo.toml.orig, all selected executable/support bytes and lock mapping. Pinned Cargo's nonexecuting metadata supplies the complete effective package/dependency/feature/target/build records for comparison with the approved original, including authors and the other build-visible package environment values. Authors retain their order; relative README/license-file strings stay exact. Only opaque package identity, the manifest location and absolute paths within the owned package root relocate. The candidate carries the original grant through that checked mapping; it never approves normalized bytes as a new original. Added support/source, changed include helpers, build targets and dependency/feature semantics refuse before package execution. Reports retain original/mapped/lock/archive/normalized-manifest/semantic hashes.

The subject-to-archive mapping admits an explicit bounded manifest surface. Cargo resolves target/build discovery and defaults; the raw parsed include/exclude/resolver/lints/badges fields require equality because metadata omits them. An empty standalone workspace may disappear in the archive. Nonempty workspace inheritance, profiles, cargo-features, unknown fields, target bench/harness settings and unsupported dependency controls such as artifact dependencies are BLOCKED/MANIFEST_SURFACE_UNSUPPORTED. They need a separately verified mapping before execution. This is a field-admission rule around Cargo, not another manifest normalizer/resolver. Existing path/source/config restrictions remain in force.

The unpublished fixture remains `sb02-feature-subject`: std-only decimal formatting plus optional JSON parsing, never a ScopeBase API. Its exact archive contains Cargo.toml, Cargo.toml.orig, Cargo.lock, src/lib.rs, LICENSE-APACHE and THIRD-PARTY-NOTICES.md. Both Cargo versions inspect that list; archive creation uses 1.88 and both compilers build the archive-derived subject. Minimal/default clients have independent roots/locks; the two-member union references one subject. Explicit subject doctests execute dependency examples that downstream tests would otherwise omit. Fixture success does not establish SB-R15 independent production consumers.

Compiler identity commands and preparation now have explicit owning rows/substages, reserved before execution. A specific recorded exception is not copied to another row, and an unrelated earlier failure cannot hide a later preparation error. Unreached stages keep null commands/not_started cleanup. After launch, collection and post-command errors retain the actual command, cwd, known group/exit state, available log paths/hashes/sizes and ordered operation/cleanup errors in the owning row. Retirement attempts and group checks apply on exceptional paths too; unestablished retirement or resource closure stays CLEANUP_UNRESOLVED with its group owner. A failed hash or size observation stays null rather than invented. No launched process is relabeled not_started because collection failed. The explicit tool-error guard handles otherwise unowned failures without guessing the first unreached row.

## Cells, elapsed bounds and controls

A logical compiler cell is a probe/compiler pair, refusal/compiler pair, or feature-member/configuration/compiler tuple. Count the full declared matrix, including optional cases/refusals, before staging; selected execution cannot make an oversized declaration valid. Maximum is 128 cells, distinct from report-stage counts. Minimal and default remain separate modes even when their resolved features coincide. Unions are nonempty feature sets with no equivalent repetitions; refusal IDs and generated row IDs must be valid/unique.

The prior validator's nonempty **outer** supported-union list restriction was removed explicitly. `supported_unions:[]` means a member advertises only minimal/default modes and no additional union profile, for example a primitive without additive features. It does not invent a fake union or establish two production consumers. The frozen SB02 matrix is unchanged: its `[["json"]]` profile and decimal/JSON clients remain mandatory, with all six compiler cells in its denominator. Schema acceptance cannot authorize removing those task-required rows.

A member without supported unions may declare one or two package clients. A
member with a supported union must retain two clients whose combined features
match that union. The clients array remains required and bounded; ordinary
client field, source and identifier validation still applies. This permits a
foundation's single boundary client without manufacturing a second consumer.
Task-specific independent-consumer and package-readiness requirements remain
mandatory at their own acceptance gates.

Each cell shares one monotonic **600-second** wall budget across sequential Cargo phases, including refusal metadata/direct compilation. At most one owned process group runs at a time. Setup/lock/archive/root-metadata commands have separate bounded individual deadlines and are not charged ambiguously to both compilers. An emitted diagnostic cannot certify a refusal stopped by timeout, log bound, interruption or unresolved cleanup. Commands preserve locked-input checks before/after execution. Timeout and cleanup/reaping outcome stay distinct; there is no guaranteed interruption of uninterruptible syscalls or compiler RSS bound.

Separate limits remain 4 MiB per stdout/stderr log, 1 MiB configuration/generated semantic fixtures, 32 features per cell and 16 MiB reports. Reports are exclusive atomic JSON; logs are referenced by hash. Exit0 applies to the requested tool scope only: inspect scope, fit, decisions_required, omitted IDs and product_qualification:false. Required FAIL uses1, malformed input2, required unavailable/NOT_RUN/unresolved execution3. Executed GAPs still need the recorded domain decisions.

Controls retain PP01–PP10: existing sibling-path variants; approved-script execution and capable fake-tool nonexecution; changed helpers and input digests; real feature leakage/union; actual doctest assertion failure; a private sentinel selected by Cargo; fixed required denominator; independent current locks; completed intended private-API refusal; delivered license/notice bytes. Repair controls traverse the actual approved-script CLI/archive path with original lock absent/present under both compilers and mutate normalized support/build/dependency/feature/author semantics after valid setup. The unchanged approved script demonstrably takes both author branches in separate owned targets; the semantic gate rejects the normalized-authors-only archive under the original grant before production targets can write its changed marker. Additional projection units cover other package metadata and unsupported raw fields. Real short owned children exercise selector/read/partial-write/wait/close/hash/stat errors, unresolved group observation and post-command errors, preserving one owning failure and untouched later stages. The tests independently retire their children even when a forced observation remains unresolved in the report. Shared-budget controls use two short real processes. Fault-injection/report predicates are not substituted for actual Cargo/API results.
