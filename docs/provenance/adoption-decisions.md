## How to use the ledger

`donors` names project, host, repository/worktree, immutable commit/tree, observed branch label, source-selection authority and policy evidence. `selected_tree_entries` is the observed subset of that tree, not a complete checkout inventory. `files` gives the selected path, full commit, SHA-256 of observed bytes, separate original-tree SHA-256 and optional dirty SHA-256, license evidence, owner, contract and source issue/test names. `source_evidence.original_observation_sha256` binds the original normalized observer record held with private preparation evidence. The preparation artifact itself is bound by `observation.source_inventory_sha256`.

`references` preserves H, G, UC, research TODO and execution-task IDs. `obligation_coverage` preserves the original 178 source-obligation mappings and appends the canonical H33 mapping, giving 179 planning source obligations, including unselected future work; attribution does not promote that work into an implementation. `case_family_inputs` retains H01–H32 unchanged and appends H33 from the canonical catalog with its explicit new-planning-obligation origin, independent oracle, known-bad control and limits. H33 records no historical donor failure or execution. `port_groups` keeps the defect explanation and named existing regressions with their responsible tasks. Root TODO remains the progress ledger.

The observer left six selected files without a port-group tag. SB01 explicitly associates KryProbe workload launch/host reader with process custody, MemVeil's native attempt decoder with capture/replay, MemVeil's lock with native dependency intake, LJ's generic ring with staging, and LJ's generic header with native ownership. These are assignments to existing obligations, not new support claims or an additional generic metadata subsystem.

## Adoption state and authorization

Schema 2.0.0 records the canonical provisional owner grant separately from each historical `license.spdx` observation. See [license intake](licenses.md) and [D03](../superpowers/specs/2026-10-18-scopebase-decisions.md#d03--license-by-code-ownership-and-actual-build-destination). The policy may be revisited. User authorization applies to owned contributions; upstream portions keep their actual offered terms, selected option and evidence. A missing header alone does not prohibit an owner-authorized port.

All 124 source observations, raw licenses and hashes remain intact. The 110 remaining unselected inputs use `NEEDS_DECISION` with null scope/role/destination/authorization/third-party classification and a reason naming the selected file. This includes the 14 former automatic NOASSERTION blocks; their candidate reference dispositions remain, but a historical label no longer mandates a copying ban. Three MojoBPF compiler implementation files remain `PRODUCT_LOCAL`/`REFERENCE_ONLY` with an explicit technical boundary and `BLOCKED`. Eleven inputs are `READY_FOR_SELECTED_SCOPE`: four exact P/O ranges for LX02 and seven K/M/O/L ranges for CP02. These retain `NOT_COPIED` as pre-copy admission observations. Their existing `OWNER-2026-10-18` authorization applies to selected user-owned host or vector contributions, with provisional Apache-2.0 destinations and preserved original license evidence. No whole-file or future-range grant follows from a selected range.

Actual PORT/ADAPT/VECTORS_ONLY completion will have a separate immutable selected-port receipt binding the ready intake snapshot, exact selected ranges, destination hashes and existing preservation map. The bounded SB01 maintenance item in root TODO implements its validator before first-port acceptance. It does not delay authorized implementation or change schema2 pre-copy semantics.

A ready metadata record requires all fields from the frozen adoption contract, contained nonoverlapping upstream fragments and retained supported options. It does not prove authorship, source-text classification, notice delivery, actual copying or package/runtime readiness. Changing source bytes, role or scope requires expert rechecking before the selected port is dispatched. Unresolved future inputs do not block independent host work or this foundation's structural acceptance.

## Validation routes

Run the following from the repository root:

```sh
python3 -m unittest discover -s tools/planning/tests -v
python3 tools/planning/check_traceability.py docs/superpowers/plans/2026-10-17-scopebase-traceability.json
```

Default validation checks JSON, stable source inventories, task/requirement ownership, obligation coverage, immutable commits, selected-path observation membership, hashes, references, every family/oracle/control and nested reference, selected regression donor/file/group/symbol/line, exact owner authorization, typed adoption states and finite role/option admission. It reports `mode: STRUCTURAL`, `source_verification: NOT_RUN`, `qualification: NOT_EVALUATED`. It does not require private SSH, prove the source observations true or run ScopeBase behavior.

Explicit source validation also reads selected immutable Git objects and verifies selected dirty bytes. Supply frozen local roots with the required history and captured working files; the illustrative paths below are not commands to recapture live donors:

```sh
python3 tools/planning/check_traceability.py docs/superpowers/plans/2026-10-17-scopebase-traceability.json --verify-local-sources --source-root O=/local/osslscope --source-root M=/local/memveil --source-root L=/local/libbpf-mojo --source-root LJ=/local/libbpf-mojo-successor --source-root J=/local/mojobpf
```

Aliases need the exact selected commits and selected objects locally. Every Git invocation disables lazy fetching, replace refs and optional locks; selected paths are matched literally. An unsupported no-lazy-fetch option or a locally missing selected object returns incomplete before any repair/fetch. A genuinely absent selected tree path remains invalid. Local donor paths are defaults only for `host: local`; provide explicit frozen-root overrides for implementation checks, including local donors, and never silently follow a copied Git pointer back to a live workspace. Remote observations require explicit local roots. No SSH, fetch, build, donor mutation or privilege escalation occurs. Exit 0 means the requested checks are valid, 2 means required source evidence is unavailable/incomplete, and 3 means invalid records or mismatched bytes. `VERIFIED_SELECTED_SOURCES` still does not mean runtime qualification or license adjudication. Check the selected frozen bytes before porting; later live changes do not invalidate that source baseline.
