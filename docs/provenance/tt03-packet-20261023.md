- Kernel findings (verified by probe 2026-10-23, encoded in driver/
  worker): the exited group leader stays visible as a zombie (state Z)
  with the tgid pinned until process exit — never assert a vanished
  leader task; `/proc/<tgid>/exe` is ENOENT once the leader is a
  zombie, so exe witnesses address a live task path; `pthread_exit`
  from a Rust main thread aborts (nounwind boundary; `C-unwind` dies
  in libgcc forced unwind), so leader-only exit uses the raw thread-
  exit syscall; `rustix::pipe::pipe()` is not cloexec — canary pipes
  use `pipe_with(CLOEXEC)` so only the explicit stderr grant crosses
  exec.
- Worker-death increment findings (verified by failing-test evidence,
  encoded in driver/worker/tests): the kernel closes a dying task's
  socket before the task becomes a zombie, so EOF/EPIPE/ECONNRESET can
  arrive while waitpid still says running — transport failures must
  consult the child across a bounded grace before reporting; the
  SCM_RIGHTS file description shares its offset, so the worker's
  positional create write leaves the parent's pulled FileA at EOF and
  partial-readback assertions must read positionally; worker Error
  detail travels hex-encoded (`diagnostic_hex`), so refusal assertions
  match hex, not plaintext.
