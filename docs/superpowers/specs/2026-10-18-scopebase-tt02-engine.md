## Exact public seam and type rules

TT02 must deliver working implementations of every definition below; declaring this contract is not implementation evidence. Existing TT01 public types/selection semantics stay unchanged. `RetirementReport` is a provider response; the runner computes the final `CleanupRecord` and cleanup state from the effect ledger, rather than accepting a submitted cleanup success.

## Bounded script grammar and the vector protocol

`OperationScript::load(bytes:&[u8], limits:&RunLimits)->Result<Self,HarnessError>` admits only the following envelope (the same exact object is nested in CaseRule):

```json
{"schema_version":1,"kind":"steps-v1","schema_id":"tt02-u64-v1","steps":[
  {"step_id":"sum","operation":"checked-add","inputs":["operands"],"parameters":[]}
]}
```

The closed structural grammar is an ordered nonempty steps array. Each step has exactly `step_id:Label`, `operation:Label`, `inputs:Vec<Label>`, `parameters:Vec<ScriptScalar>`. step_id is unique within the script; input names are unique within a step and refer to slots in its vector row. At most 16 inputs and 16 parameters per step. ScriptScalar has exactly one of three tagged forms: `{"kind":"u64","value":"7"}`, `{"kind":"bool","value":true}`, or `{"kind":"bytes","hex":"00ff"}`. Hex is even-length lowercase, no separators, at most 4,096 decoded bytes per scalar. All decoded byte allocations count toward retained limits. No other scalar kind, null, generic JSON object, shell text, file path, environment interpolation, branch, jump, loop, implicit retry or function evaluation exists in this grammar. Statements execute in array order in the adapter; TT02 does not implement a general script interpreter.

This addendum freezes the shipped test/client adapter dialects below; these are real reference implementations in the delivered harness corpus/clients, not a claim of new production ScopeBase capabilities or required builtin adapter exports. A custom adapter's reviewed case registration can define another schema_id/operation vocabulary using the same bounded envelope; the engine transports that exact frozen script and has no claim to implement its semantics. Such a registration must supply an actual adapter/oracle/fixture, their exact bindings, fixtures and wrong-value controls before its case can become executable. Unknown structural `kind` values are always invalid. Shipped vector adapters reject any schema/opcode/arity/parameter combination outside this table as UnsupportedSchema before reading operation data; they cannot declare it supported or qualify it by echoing output.

| Shipped schema / operation | Exact input and output contract |
|---|---|
| `tt02-u64-v1` / `checked-add` | One input slot, no parameters. Input is exactly two ASCII canonical decimal-u64 lines, each LF terminated, no CR/trailing bytes. Checked addition; success output for this step is canonical sum text without LF; overflow produces typed operation Refused, actual cause Unknown, and can only be tested by an AssertionOnly contract |
| `tt02-u64-v1` / `decimal-length` | One input slot, no parameters; exactly one canonical decimal-u64 line with LF. Output is canonical decimal digit count without LF. Independent expected vector supplies the number; do not use the same production formatting helper for oracle truth |
| `tt02-refusal-v1` / `emit-model-outcome` | One input slot, no parameters. Exactly one script step. Strict model transcript as defined below; return its observation/error payload under the actual InvocationKey and that step_id. This is explicit deterministic model transport, not BP03 cause inference or a real BPF adapter |

The u64 adapter observes every ordered step, returning the strict bytes schema `{"schema_version":1,"kind":"tt02-u64-observation","steps":[{"step_id":"sum","value":"5"}]}`. A failing step stops later steps and reports exact step_id, completed_steps and a partial_observation containing the preceding successful step results; unexecuted step triggers remain missing. The runner gates claimed step coverage against explicit progress as well as the independent ledger, so a preauthored ledger cannot make an unexecuted step active. Observed.completed_steps must exactly equal the entire ordered script step list; CaseError.completed_steps is an exact ordered prefix, and a present failing step_id is the next step. Trigger/ActiveExcluded coverage requires every named step in that prefix or the explicitly attempted failing step; Positive coverage requires completed steps; Setup requires successful prepare plus its independent ledger. An attempted refused step may establish a trigger without establishing positive success. Missing participation gates effective achieved to zero while retaining the raw ledger count; oracle checks that depend on it are NotJudged. The independently authored expected-vector schema is `{"schema_version":1,"kind":"tt02-u64-expected","steps":[{"step_id":"sum","value":"5"}]}`. Required named assertions compare step identities and literal values against this separate file. Neither side fills the other from its serializer.

Model transcript envelope is `{"schema_version":1,"kind":"tt02-model-outcome","outcome":...}`. Outcome is either `{"kind":"observed","schema_id":Label,"schema_revision":u32,"bytes_hex":string}` or `{"kind":"error","stage":Label,"category":CaseErrorCategory,"errno":i32-or-null,"cause":RefusalCause,"diagnostic_hex":string}`. No InvocationKey, effects, verdict, expected value or qualification is accepted in this transcript. The model adapter binds the current key and one-step completion/error progress, emits an empty complete EffectBatch, and the independent oracle reads a separate expected file with exactly `schema_version:1`, `kind:"tt02-model-expected"`, and `expected_outcome` using the same closed inner observed/error forms. The expected file never supplies verdict/capability fields. The model oracle compares selected payload/stage/cause/diagnostic relations against independently authored literals; it does not accept the observed cause label without its matching independent witness. For a model error it binds completed_steps=[] and partial_observation=null, and uses RefusalEvidence method `literal-model-transcript`, the input artifact ID and tier T0. Diagnostic evidence is inert bytes. It may not execute a command or assert live activity. H33 expected fixtures enumerate the literal independent cause/result matrix; same-errno controls change the relevant independent witness and keep all unrelated inputs fixed.

`VectorBundle::read` requires one caller-opened regular File for each manifest file, no extras or duplicate file IDs. Digest/length identifies the observed sequence; retained vector bytes, rather than a later reopening, are what the adapter/oracle use. Holding a File or matching its stat tuple does not prove immutable backing storage.

## Frozen subject/build recipe and actual byte checks

Expected and observed identities have different causal sources:

1. Before discovery, the controller chooses the exact archive/source manifest, permitted resolved dependency/features/backend, compiler/target/build options, suite/oracle/fixture versions and final-object list. `RunContract` freezes those requirements. No field is obtained from `adapter.subject()` to make it match itself.
2. The actual standalone consumer build records its resolved library source/archive mapping, precise feature union, lock, selected backend, compiler identity, target and build flags from the existing build harness. The manifest is generated from measured selected inputs. Dirty source uses a complete source inventory/patch identity, never Git SHA alone. It is emitted beside that consumer, not generated by a testkit-owned alternate production dependency.
3. Measure the final consumer executable after linking and each final object/worker/data artifact actually used. This second stage avoids a self-hashing executable cycle: the build-input hash excludes final executable bytes; the external execution manifest binds the executable digest to those inputs. The admission route measures executable/object artifacts using the bounded streaming meter and retains only their digest/length/binding; vector bytes are separately measured and retained under the 8 MiB cap. Runtime loaded bytes must be the verified retained bytes/handle in the relevant later backend; TT02 cannot prove a custom adapter obeyed that requirement.
4. Exact comparison covers package name/version, source, lock/build inputs, features, backend/version/source, host/target, consumer and every required artifact. Compare at entry and after execution; drift makes the report invalid. Expected absence differs from unknown. A digest match alone cannot upgrade `SelfReported` provenance.

For this implementation, reuse the existing build-policy original-source/archive mapping rather than inventing a second directory hash: `source_sha256` is its `original_source_sha256`, and the matching actual archive hash is a separate artifact. `build_inputs_sha256` hashes UTF-8 JSON encoded with sorted object keys, separators `(',', ':')`, `ensure_ascii=True`, no newline and no floats. The exact object has `schema_version:1`, subject name/version/source/archive hashes, generated lock hash, resolved package records sorted by `(name,version,source)` with source hashes and sorted features, backend record or null, host/target, compiler/Cargo/rustdoc executable hashes, ordered compiler/linker arguments and consumer-source inventory hash. Source/archive/build/executable identities never substitute for one another.

`bind_consumer.py` takes `--expected EXPECTED_INPUT_JSON --build-record ADMITTED_RECORD_JSON --metadata ACTUAL_CARGO_METADATA_JSON --executable OPENED_EXECUTABLE_PATH --output NEW_FILE`. It strictly validates bounded inputs, compares expected inputs against actual admitted archive/source/lock/feature metadata, measures the actual completed executable and explicitly listed artifact files, and writes an immutable generated measurement manifest. It never calls Cargo, fetches, infers expected features from the observed graph or decides qualification. Missing source/build/link evidence yields incomplete binding; a supplied label cannot replace that record. Its tests use independent fixed metadata and real temporary files, including swapped archive/executable/features and a valid restored twin.

The supported package harness need not gain new hooks. Its member policy admits at most two client entries, and the current minimal/default route runs only the first client; testkit has no feature union. Keep both TT01 client sources and use the accepted explicit-client task-driver route to build/run every original TT01 and new TT02 client against the exact archive. Do not put four clients in member policy or claim the common helper alone executes second clients. Minimal/default remain explicit matrix cells even when their feature semantics coincide. The driver executes each client’s self-contained model checks. An additional bounded task driver reads the retained actual client build records and binary paths, invokes the post-build binder, then executes those **same binaries** with explicit expected and observed manifest arguments. The client compares frozen expected input to the actual generated measurement and separately reports this binding exercise. A client's ordinary self-reported model run may deliberately remain provenance-limited; its exit zero means its asserted engine expectations passed, not that a domain profile qualified. The generated-measurement replay supplies the actual-consumer binding evidence.

`BindingProvenance` is `GeneratedBuild{manifest_sha256,measurement_sha256}` or `SelfReported{reason}`. These are descriptive claims, not cryptographic trust tokens. The supported archive route produces and independently verifies the generated manifests. A custom declaration is permitted for diagnostics but leaves a required generated-build binding incomplete. Incoherent/mismatched values are invalid. No runtime credential/capability, source grant or kernel support follows from provenance labels.

Actual archive controls must change the linked input rather than edit only its label: build consumer A against admitted archive A and another bounded control against a distinct explicitly approved source/archive B at the same 0.1.0 version, retaining the actual metadata. The frozen A expectation must reject B. Reuse the existing admitted `sb02-feature-subject` minimal/json build populations for an actual resolved-feature binding control (the pure fixture is not a ScopeBase product); do not add pretend testkit production features. Version and absent-backend mismatch controls are bounded metadata controls unless their actual alternate build is separately admitted. A model field-control is explicitly not a real backend test; do not create a pretend production backend just for it.

## Runner binding and execution state machine

The runner is sequential: `Entry -> ContractSnapshotted -> MetadataBound -> Preparing -> Executing -> Collecting -> Judging -> CaseRetiring -> Recorded`, repeated, then `RunRetiring -> FinalBindingCheck -> Terminal`. Required positive twins precede dependent cases; ties use `(case_id,revision,cell_id,attempt)`. Reject twin cycles/self-links before prepare. Operation IDs and attempts are frozen by the contract, never allocated according to discovered availability. There is no automatic retry: every planned attempt contributes and a failed attempt is sticky.

The honest prelude is:

1. Record a monotonic entry instant **before** invoking `fixtures.contract()`. This method is custom code, so no claim that the runner has invoked no hooks is possible. Its contract, and those of subject/identity/cancellation introspection, forbids acquiring resources, environment discovery or other effects. Neither `&self` nor the probe acquisition's `&mut self` enforces that promise or prevents blocking.
2. Call contract exactly once, clone the already admitted immutable value within its retained-byte bound, compare its full plan to the external plan, and validate its limits. It must originate from independently selected controller inputs, not from adapter output. The selected execution deadline is `entry + execution_ms`; time spent in contract() is charged retrospectively when it returns. If it has already expired, enter no prepare/execute/collect operation.
3. End the contract borrow, then acquire the independently owned cancellation probe at most once if the entry-relative deadline has not already expired. Acquisition is a no-effects metadata hook; its full elapsed time is included before after_contract. Take that existing checkpoint through the probe, or record an expired null poll without acquisition. Retain the same probe through completion, including while prepare lends FixtureAccess; see the exact [acquisition rules](2026-10-18-scopebase-tt02-cancellation.md#exact-prelude-and-call-order).
4. Call adapter.subject() then oracle.identity(), with cancellation/deadline checkpoints before and after each. Compare with the frozen contract; never derive expected fields from these returned values. A mismatch is invalid before operation preparation. These are metadata hooks with a no-effects obligation, not a sandbox or an enforceable hard timeout.
5. Only after metadata binding succeeds may prepare/execute/collect run. An owner becomes Participating for that invocation immediately **before** its first effect-capable method is called: fixture on prepare, adapter on execute. Record that entry before invoking it, so a returned error/malformed response cannot erase the cleanup obligation. collect is part of fixture participation. Admit prepare access.effects before execute; drop the borrowed access before invoking collect on the session. Admit each returned outcome/error/expected effect batch exactly once and require its owner/origin to match that call. Oracle evaluation is required to be pure and has no native-owner role.

For UNIMPLEMENTED/NotRun invocations neither owner participates, so their derived cleanup is NotRequired without a retire callback. For any participating owner, retirement is scheduled even if its returned effect list is empty. A contract/subject/identity/cancellation hook violating its no-effects promise is outside the trustworthy protocol; metadata cannot discover its hidden owners. The runner cannot guarantee cleanup or a terminal result when arbitrary custom code blocks, panics or aborts. It does not catch panics as semantic negatives. TT03/TT05/TT07 own stronger supervised process boundaries.

Sample cancellation through the same independently owned probe before and after each external non-retirement stage; never borrow the fixture session for a poll while FixtureAccess is live. On cancellation, execution deadline or invalid protocol, stop admitting new operations, retain all received data, mark remaining planned invocations NotRun, and perform the applicable retirement schedule. A valid case-local prepare/collect failure or a non-cancellation operation CaseError closes that invocation and retires its owners, then continues the next scheduled invocation; it does not hide later independent assertions. Prepare failure cannot be evaluated as an operation-under-test error; a valid operation-stage CaseError, including expected refusal and bounded partial-step progress, can. Explicit Cancelled/TimedOut outcomes stop new operations. A failed collect leaves its dependent assertions NotJudged; independently valid previously collected evidence remains available. The fixed normal-work deadline is never refreshed. Retirement is allowed after it using the separate cumulative retirement allowance. If deadline/cancellation prevents the final subject/identity recheck, that missing binding check is incomplete, not an assumed match. After successful retirement and a permitted final recheck, compare subject and oracle identity again; do not reread contract().

## Effect ledger and retirement reconciliation

A report records descriptive custody, while actual owners remain in the borrowed adapter/session after run_profile returns. Native cleanup is done only by those owners. The engine never closes guessed FD numbers, kills PIDs or reconstructs handles.

Define the exact provider/result records as follows. All input lists are bounded and sorted by ID except transitions, which retain chronological order.

| Record | Exact fields and semantics |
|---|---|
| `EffectBatch` | `registrations:Vec<EffectRegistration>`, `complete:bool`. An empty complete list reports no effects from that call. complete=false creates a runner-owned uncertainty for this owner/invocation, in addition to every known registration |
| `EffectRegistration` | `resource_id:Label`, `owner:Adapter/Fixture`, `origin:InvocationKey`, `kind:Label`, `identity_sha256:Digest256`, `recovery_evidence_id:Option<Label>`. ID is unique across the run; immutable tuple is `(run,resource_id,owner,origin,kind,identity_sha256)` |
| `PendingEffectRef` | `resource_id`, `owner`, `origin`, `identity_sha256`; exact equality to the existing registration |
| `EffectTransition` | `transition_id:Label`, `effect:PendingEffectRef`, `to:"retired"`, nonempty bounded `evidence_ids:Vec<Label>`. The only transition is Pending -> Retired. Every transition ID is run-unique and every resource can make this transition once |
| `CleanupScope` | `Case(InvocationKey)` or `Run(RunId)`; no arbitrary scope label |
| `RetireRequest` | Runner-created `call_id:u64`, owner, exact scope, fixed `deadline:Instant`, `remaining:Duration`, `known_pending:Vec<PendingEffectRef>`, `uncertainty_ids:Vec<Label>`, remaining record/retained-byte allowance. No public admission constructor; accessors only |
| `RetirementReport` | `call_id`, owner, scope, `discovered:Vec<EffectRegistration>`, `transitions:Vec<EffectTransition>`, `pending_snapshot:Vec<PendingEffectRef>`, `complete:bool`, optional bounded diagnostic. complete describes reported inventory completeness only; it submits no derived CleanupState/Qualification or mutable original-scope field |
| `CleanupRecord` | Runner-created `call_id`, `owner`, `scope`, `status`, `response:Option<RetirementReport>`, `error:Option<CleanupError>`, `state_at_case_end`, `state_at_run_end`, `pending_ids`, `uncertainty_ids`, `hook_elapsed_ns`, `remaining_before_ns`, `remaining_after_ns`, `phase_elapsed_ns`, `transition_ids`. Call status is `Called/CalledOverBudget/UncalledNoParticipation/UncalledBudgetExhausted`; all timing counts are canonical decimal-u64 |

CleanupError is `InvalidProtocol/LimitExceeded/BudgetExhausted` plus bounded diagnostic; absent response is explicit null. Each scope's two records share phase_elapsed_ns, the total charged once for that phase, and preserve hook elapsed separately. Uncalled records have zero hook elapsed. Relative remaining values must be nonincreasing and agree with the fixed-phase/cumulative schedule; imports validate that accounting but cannot authenticate a reported clock. Run-scope records use state_at_case_end=null and the final derived state_at_run_end.

Any reuse of resource_id in a new registration is invalid, even if identical: repeated state belongs in a pending snapshot, not another registration. Re-registering a retired ID or changing owner/identity/origin is invalid. Each called effect-producing response's actor must match the registered owner. Registration via a case response must use that exact invocation as origin. Per-case `max_effects` and global limits charge registrations before growth. A malformed/oversized effect response retains bounded known entries plus an uncertainty record; it is invalid and cannot manufacture clean custody.

Repeated **unchanged pending snapshots** on different call IDs are valid and have no state transition. Duplicate resource IDs within one snapshot are invalid. Replaying any transition, including an identical transition ID/body, is invalid. A Pending -> Pending or Retired -> Retired transition is not a permitted protocol kind. The only way to remove a known pending resource is a valid explicit transition with its exact immutable tuple and nonempty evidence reference. Omitting it from a claimed complete snapshot is invalid, not retirement.

Per-case retirement may reference only that owner's resources whose origin equals the exact InvocationKey. Case B cannot settle case A. Run retirement may explicitly settle an outstanding resource from an earlier invocation **of the same run and owner**, but must carry its original InvocationKey/identity in the transition. This is an explicit parent-scope reconciliation rule, not changing its origin to Run or treating an empty run snapshot as proof. At run scope the pending snapshot must contain the complete remaining pending set for that owner across all case scopes. A run report without an explicit transition cannot erase an earlier pending case resource.

`discovered` is allowed during retirement for previously unreported resources, provided owner/origin are exact and origin is one of that owner's participating invocations inside the requested scope. It still consumes the original case/global budget. Discovery does not authorize creating new work during cleanup. A resource discovered and retired in one response has one registration followed by one explicit transition; both are retained. Previously reported unknown custody (`EffectBatch.complete=false`, malformed response, or `RetirementReport.complete=false`) remains an explicit uncertainty in v1 even if all **known** resources later retire. V1 has no generic protocol capable of proving that an unknown native inventory is now complete. Such uncertainty cannot be silently cleared by a later complete=true/empty snapshot; this conservative limit is deliberate. Later owner-specific recovery may preserve an independent recovery record but cannot rewrite this completed TT02 receipt into qualification.

Case cleanup records preserve `state_at_case_end`. If a valid later run-scope transition retires a known pending case resource, `state_at_run_end` may become Complete with a reference to that exact transition. The original unresolved observation remains. Semantic failures and uncertainty are never cleared by this reconciliation. Dropping the owner or exiting zero supplies no transition.

Derived cleanup state is:

- **NotRequired** for an owner that never participated in the scope and has no effects/uncertainties; no callback is needed. Also NotRequired after a valid called retirement when that owner has never registered any effect or uncertainty within the scope and reports a complete empty pending snapshot.
- **Complete** when every known effect in that scope is explicitly retired, no uncertainty remains, and the required participating-owner retirement call completed with a valid complete response. At least one effect existed; an empty never-used scope is NotRequired instead.
- **Unresolved** for any remaining known pending resource, uncertainty, participating-owner call not made because budget was exhausted, or incomplete retirement response. Contradictory/malformed responses additionally set harness Invalid.

### Exact cumulative retirement schedule

Each run has one `retirement_ms` allowance, measured with monotonic Duration precision over retirement phases, including their validation/accounting time. No initial zero configured allowance is allowed, but remaining allowance can become zero. Callback order is adapter then fixture for each case, followed by adapter then fixture for run scope. No participation derives the uncalled NotRequired record. For a participating owner, execute this algorithm:

1. Maintain cumulative elapsed time of **closed** retirement phases. At the next phase start set `phase_start=now` and checked `phase_deadline=phase_start + max(0, configured_allowance - closed_phase_elapsed)`. This deadline is fixed for both owners. At every checkpoint derive remaining from `max(0, phase_deadline-now)`; count current phase elapsed once, never both as a phase and as a separate hook debit. Use Duration/nanosecond precision, without rounding each call down to milliseconds.
2. If remaining is zero, **do not call** the hook with a zero budget. Record UncalledBudgetExhausted, preserve all known pending resources, add an unclosed-scope uncertainty for a participating owner, and derive Unresolved. An empty reported effect list before this point is not proof that the omitted retirement succeeded. A never-participating owner still gets UncalledNoParticipation/NotRequired. Exhaustion of an entered phase sets the run's budget-compliance gate Incomplete.
3. Otherwise enter the hook once with the fixed deadline/request. On return, record its exact elapsed interval and preserve valid reported transitions, even if late. A return past the fixed deadline is CalledOverBudget; it exhausts the shared allowance and sets the budget gate Incomplete. A later participating owner is not called when none remains. A timely return followed by bookkeeping that consumes the rest also leaves subsequent owners uncalled; it cannot refresh their allowance.
4. A malformed return consumes the same phase time and creates invalid protocol plus unresolved custody. A subsequent owner is still offered its scheduled call if positive allowance remains. There is no automatic retry. Cancellation does not suppress a retirement callback while positive allowance remains.
5. Close a phase by adding the full `phase_end-phase_start` to cumulative elapsed using checked/saturating accounting; overrun is preserved in the reported elapsed value and remaining saturates at zero. Intervening ordinary execution is outside this cumulative retirement budget and remains subject to the fixed execution wall deadline. Exactly `2 * planned_invocations + 2` slots are assigned at admission: for scheduled zero-based invocation i, adapter call_id=2*i+1 and fixture call_id=2*i+2; final run calls are 2*N+1 and 2*N+2. Never-entered invocations still have uncalled NotRequired slots, so partial execution cannot change IDs or the denominator. Run scope is always accounted for, including partial execution, and never replenishes a case's allowance.

Thus an adapter overrun can leave a participating fixture uncalled/unresolved even when the adapter returned a complete response. If the fixture never participated, its derived NotRequired is legitimate. A hook that does not return can still block indefinitely; the deadline is a cooperative contract, not an interruption or destructor guarantee. No timeout/zero-exit statement substitutes for resource retirement.

## Intent, cause and capability matrix

The **qualifying** matrix is closed. Actual outcomes outside a qualifying row remain recorded; they do not fall through to another intent or get coerced into support. Unknown JSON kind/enum values are Invalid. Known but insufficient capability/cause/outcome evidence is Incomplete unless an independently judged semantic Fail has higher precedence.

| Frozen intent | Outcome needed for qualification | Capability permitted for qualification | Cause/twin requirements |
|---|---|---|---|
| PositiveSupport | Completed Observed outcome with every required assertion Pass | Supported only | At least one required Setup, Trigger and Positive population, each positive minimum; no expected cause/twin field |
| ExpectedRefusal(Permission) | OperationError with the intent's exact step_id/stage, category Refused | Denied only | Actual cause Permission; selected functional PositiveSupport twin and equivalence assertion |
| ExpectedRefusal(Verifier) | Same operation-error requirement | Incompatible only | Actual cause Verifier; same twin/equivalence requirement |
| ExpectedRefusal(License) | Same operation-error requirement | Incompatible only | Actual cause License; same twin/equivalence requirement, including H33-specific witness and actual/model tier boundary |
| ExpectedRefusal(UnsupportedOperation) | Same operation-error requirement | Unsupported only | Actual cause UnsupportedOperation; same twin/equivalence requirement |
| AssertionOnly | Any well-formed operation outcome judged by its frozen assertions | Unknown or NotApplicable only | No positive_twin or expected cause fields. A correctly asserted unknown/inconclusive result can qualify only this assertion claim; it establishes no positive capability |

Each ExpectedRefusal rule requires at least one positive-minimum Setup and Trigger population for its intended step. Its step_id must be in the script and its frozen stage must be nonempty; neither comes from the returned error. ExpectedRefusal(Unknown) is an invalid **contract**. Actual Unknown cause in a cause-specific refusal case is valid evidence of uncertainty, but cannot qualify that case. AssertionOnly with Supported/Denied/Unsupported/Incompatible evidence is recorded but cannot qualify; it may not bypass a missing refusal twin by changing its report intent. These restrictions concern the computed claim; they do not discard observed facts or infer causes from errno.

A functional twin means: exact selected case/revision/cell; intent PositiveSupport; all its planned attempts have completed observations, valid matching subject/artifacts, all required assertions Pass, coverage complete, and capability Supported. It is not a profile verdict, so there is no recursive qualification dependency. Its later cleanup may still make the overall profile incomplete. A blocked/missing/failed/inactive twin is not functional. The required `equivalence_assertion` belongs to the refusal case and must explicitly reference the twin and its independently recorded comparable workload/context/object relation; merely sharing errno or library version is insufficient.

Every ExpectedRefusal case includes named `refusal.intended-cause` and its equivalence assertion. Both have `requires_positive_twin=true` and list all setup/trigger coverage required for their judgment. The independent oracle returns NotJudged for an unknown cause, Pass for the exact established intended cause, and Fail for a **known wrong** cause or unexpected success only when the named setup/twin/trigger prerequisites support that conclusion. Engine gating converts any submitted Pass or Fail to NotJudged when its declared prerequisites are missing; it retains the raw oracle check plus gating reason, so omitted activity cannot become a valid negative control.

This gating is per assertion, not all-or-nothing. Example: refusal twin is blocked, so `refusal.intended-cause` is NotJudged; another assertion `input.license-bytes` requires only an independently read fixture and has a known wrong value. That assertion remains Fail and the profile is Failed, while missing twin/coverage stays visible. If the independent byte check passes and only the twin is missing, the verdict is Incomplete. Do not mask that valid Fail because another branch cannot be judged. ActiveExcluded populations are mandatory wherever the frozen case lists them; simply declaring an excluded target ready never supplies its activity count.

Fold Invalid > Failed > Incomplete > Qualified using all required attempts and dimensions. Invalid bindings/harness/record transitions win; otherwise any ungated semantic Fail wins; otherwise any missing evidence, prohibited qualifying matrix combination, missing final identity check, DRAFT/open owner/unimplemented cell, deadline/budget failure or unresolved custody is Incomplete. Qualified requires all selected rows/attempts/assertions/coverage, matrix predicates, bindings and final cleanup acceptable. Optional diagnostics cannot change the required denominator. Refusal qualification never changes its capability to Supported, and AssertionOnly never certifies a support claim.

### Sampling and deadline semantics

Let `D = contract.limits.execution_ms * 1_000_000`, checked in u64. All elapsed times share the single monotonic entry instant sampled **before** contract(). The deadline is entry+D and never restarts after a case or retirement. Elapsed time includes retirement and ordinary bookkeeping. Its separate cumulative retirement allowance does not move this normal-work deadline.

At each sampled checkpoint:

1. Record poll_started_elapsed_ns. If it is already >= D, do not call cancellation_requested(); set cancelled=null and poll_finished_elapsed_ns equal to poll_started_elapsed_ns. This is a recorded deadline stop, never a false cancellation result.
2. Otherwise call the independently owned probe's no-effects cancellation_requested() metadata hook exactly once, record its Boolean return, then poll_finished_elapsed_ns. This call is not recursively checkpointed. Require finished>=started; cancelled is non-null in this branch. A cancellation hook can itself block or cross the deadline; its elapsed time is included when it returns.
3. Derive `cancel_stop = cancelled == Some(true)` and `deadline_stop = poll_finished_elapsed_ns >= D`. A gate permits normal work only when neither is true. Preserve both predicates when both are true. No serialized gate verdict or chosen stop reason substitutes for these raw fields.

Elapsed values beyond D are valid evidence of overrun, not an invalid timestamp merely for exceeding the configured budget. Checked conversion/monotonic-clock accounting failure cannot yield Qualified; use the existing error/partial-report path rather than wrapping or inventing a timestamp. No hard interruption guarantee is added.

The runner records the after sample of every **returned** metadata/prepare/execute/collect/judge call, including a returned error. An operation CaseError Cancelled/TimedOut also independently closes normal work under this addendum; its returned outcome remains the source of that fact. A non-cancellation case-local failure does not close the whole run. Retirement callbacks are not suppressed by these normal-work stops and retain this addendum’s separate schedule.

Once any checkpoint observes cancellation/deadline, or existing evidence establishes a run-stopping outcome/protocol/binding failure, normal work stays stopped even if a later cancellation poll returns false. The importer derives this latch by walking the fixed records; there is no authoritative submitted `stopped`, first-stop or reason field.

Compute the case/ledger fold before the completion sample. Sample completion once as the last custom metadata call, then add its predicates and finalize the terminal without further custom hooks or effects. Qualification is as of that completion checkpoint. Cancellation after it is not retrospectively observed; receipt serialization is a separate bounded operation. This states the cooperative boundary rather than promising an impossible atomic flag-and-return interval.

### Fixed order, omissions and partial records

The structural traversal order is after_contract; entry_subject before/return/after; entry_oracle before/return/after; each scheduled invocation's prepare/execute/collect/judge before/after pairs in order; final_subject before/return/after; final_oracle before/return/after; completion. Case and run retirement retain their existing intervening state-machine positions. contract_returned_elapsed_ns precedes after_contract. All recorded times are nondecreasing in this traversal; within a returned metadata record, before.finished <= returned <= after.started <= after.finished. Add the elapsed time of each cleanup phase only once; it cannot exceed the total elapsed time visible by completion. This consistency check is not clock authentication.

A full receipt (non-null run_terminal) has sampled after_contract and completion. No slot is not_recorded. Every entered case stage has sampled before and after gates, and its before gate must permit entry. Every returned metadata value has both samples. All field names remain present even for work that did not run.

For a call that was not entered, its after slot is omitted/not_entered and metadata value/returned time, when applicable, are null. Its before slot is either the actual sampled stopping gate or an omission justified as follows:

| Cause | Allowed before slot / independently reconstructed premise |
|---|---|
| `prior_stop` | Any later normal-work call; an earlier sample, explicit Cancelled/TimedOut outcome, or recorded binding/protocol failure has already closed normal work |
| `case_not_executable` | A case stage; its exact selected catalog member is UNIMPLEMENTED or otherwise non-executable under the frozen existing rule; its entered_stages is empty and execution is NotRun |
| `stage_not_reached` | A later stage in this invocation; preceding recorded case-local failure or absent prerequisite outcome/expected evidence prevents that stage under this addendum. Cannot omit a required later independent invocation |
| `cleanup_unresolved` | Final metadata only; the completed run retirement ledger is unresolved, so this addendum’s successful-retirement precondition is absent. Both actual final values stay null and the final-check gate is incomplete |
| `no_executable_members` | Entry/final metadata only; the nonempty frozen required selection has zero executable members, as specified below |
| `not_entered` | After slots only, paired with a call that was not entered; cannot suppress a returned call's after sample |

A metadata before gate that permits entry cannot be followed by a null value in a full receipt. A before gate that stops cannot accompany a returned value or an entered case stage. Metadata skipped without a supported omission cause is invalid protocol; unavailable final values always leave the final-binding predicate incomplete. There is no invented metadata-hook error return: the existing subject()/identity() signatures are infallible. “Unavailable final check” means a justified uncalled hook, or explicitly unrecorded partial evidence, not an invented successful empty binding.

For a partial receipt with run_terminal=null, not_recorded is permitted only at an unfinished tail of normal-work evidence, never between later sampled/returned normal-work records. Retained cleanup records may still describe attempted recovery after that partial boundary. A returned metadata value/time may precede a not_recorded after slot; this preserves the actual value and incomplete post-call checkpoint. A sampled permitted before gate with no value/after observation proves neither that the metadata call ran nor that it returned. Missing observations are incomplete, not a comparison match or false cancellation sample. Existing partial case/cleanup rules still apply. A false omission premise, reversed timestamp, duplicate/unknown field or impossible entered-stage/sample combination remains invalid even in a partial receipt.

No-case, no-effects and incomplete prelude paths still account for all admitted deterministic cleanup slots as UncalledNoParticipation/NotRequired if a RunReport is returned. A custom hook that never returns/panics/aborts may prevent any report; the schema is not a recovery/sandbox mechanism.

### Pure reconstruction and before-effects errors

RunReport::from_json reconstructs, in this order:

1. Bind the external contract/catalog/selection and existing record keys as specified above; validate this fixed observation grammar, ordering and omission premises.
2. Compare **each available** entry and final subject/oracle value with its corresponding frozen expected binding. Any well-formed mismatch contributes Invalid, including a final-only source/features/backend/object/consumer or oracle change. Also compare entry/final values directly; equality to the external expected values already implies equality to each other. Missing final values contribute Incomplete and cannot be filled from entry values.
3. Derive every cancellation/deadline predicate and the sticky normal-work stop from samples and existing explicit outcomes. A stop after the last successful case, including at final metadata or completion, contributes Incomplete. Entering a later normal-work call after a prior stop is invalid protocol. Independently valid semantic Fail remains higher precedence than these incomplete gates; metadata/binding Invalid remains highest.
4. Combine these dimensions with the existing case/coverage/capability/cleanup fold using Invalid > Failed > Incomplete > Qualified. Then compare any supplied terminal qualification/reasons to the computed result. Terminal reasons are output only. Contradictory summaries return InvalidProtocol; they are never the source of a missing gate.

Use exact computed runner reason labels `runner.cancelled`, `runner.deadline`, `runner.entry_subject_missing`, `runner.entry_oracle_missing`, `runner.final_subject_missing`, `runner.final_oracle_missing`, `runner.entry_subject_mismatch`, `runner.entry_oracle_mismatch`, `runner.final_subject_mismatch`, `runner.final_oracle_mismatch`, `runner.observations_partial`, and `runner.no_executable_members` when the respective condition exists, together with this addendum’s other derived reasons. Include every applicable label, sorted/deduplicated. A coherent well-formed mismatch receipt may return an Imported report whose recomputed qualification is Invalid; a receipt falsely claiming Qualified for that evidence is rejected as contradictory. Coherent fabricated samples remain untrusted Imported claims, as before.

A truly invalid prelude **before any effect-capable call** may return `Err(HarnessError)` with partial_report=None: contract/selection admission mismatch uses its existing kind; entry subject/oracle mismatch uses InvalidBinding. The error must not claim a completed or qualifying run, and no prepare/execute/collect/retire callback has been entered. This is a legitimate no-report path; there is no invented run receipt for from_json to reconstruct. If an implementation instead preserves an admitted prelude report, it must use these actual observations, all attempts NotRun and cleanup NotRequired. After any effect-capable entry, this addendum’s retirement and partial-report preservation obligations remain mandatory; this exception cannot discard received effects.

A mere cancellation/deadline gate with an admitted contract is not an InvalidBinding shortcut. Return a complete Incomplete report when execution can finish its bookkeeping/retirement, or the existing honest partial report when it cannot. Never manufacture a binding mismatch to avoid recording that gate.

### Zero executable members

**An empty required selection is invalid. A nonempty required selection with zero executable members is admitted, within the existing limits, and remains Incomplete.** It records every planned attempt as NotRun, no entered stages, case_not_executable before-stage omissions, and uncalled NotRequired cleanup slots. No prepare, execute, collect, judge or retire hook runs. Entry/final subject/oracle hooks are unnecessary for this path and use no_executable_members omissions; contract(), at most one in-budget probe acquisition, and the after_contract/completion cancellation samples remain no-effects metadata operations. A valid external caller need not invent an executable member or probe an environment. DRAFT/open-owner/UNIMPLEMENTED gates remain separate visible reasons; a nonempty all-UNIMPLEMENTED profile is not rejected merely for having no executable members.

There are exactly four metadata observation slots, two run checkpoint slots, and eight case checkpoint slots per planned invocation: at most `8 * case_attempts + 10` checkpoint samples (32,778 at the existing maximum). There are no caller-chosen event names, dynamic event handlers, retries or additional clocks. All records and copied metadata count toward the existing retained/receipt/edge limits; reserve their mandatory representation before effects. Do not increase parser/vector/receipt limits. No new dependency or hashing rule is required.

## Exact limits and bounded artifact measurement

`RunLimits` is an admitted value with the following complete construction API. `RunLimitValues` is a public input struct with exactly the u64 fields in the table; it is not itself an admitted limit. `LimitError` identifies the field, requested value, applicable maximum and either `Zero/AboveMaximum/NotLower/CrossField/PlatformOverflow`. Wire limit values use the same canonical decimal-u64 strings as other counts.

```rust
impl Default for RunLimits { /* exactly the defaults below */ }
impl RunLimits {
    pub fn new(values: RunLimitValues) -> Result<Self, LimitError>;
    pub fn values(&self) -> RunLimitValues;
    pub fn maxima() -> RunLimitValues;
    pub fn lowered(&self, requested: RunLimitValues) -> Result<Self, LimitError>;
}
```

`new` validates each positive value against its hard maximum and the cross-field rules below. It permits valid non-default values: use `let mut v=RunLimits::default().values(); v.execution_ms=60_000; let limits=RunLimits::new(v)?;`. `lowered` performs those same checks and additionally requires **every** requested field to be no greater than the corresponding receiver field; calling default.lowered with execution_ms=60_000 fails. It never silently clamps or raises a value. `RunContract::load` uses `ceiling.lowered(manifest_limits)`, so a caller that wants a 60-second contract must deliberately supply a compatible constructed ceiling. The entire requested value is explicit; omitted fields are invalid. There is no builder that quietly restores defaults.

Every sum/product/offset/usize conversion and monotonic deadline addition is checked; a platform that cannot represent the requested value refuses it. Cross-field validity does not promise every maximum-sized combination fits: admission additionally checks the **actual** complete selection, mandatory record reservation and aggregate buffers. No truncation/filtering is allowed to make it fit.

Derived bounds are at most `2 * case_attempts + 2` cleanup call slots, at most effects_total accepted retirement transitions, and at most `8 * case_attempts + 2` uncertainty records. The latter covers one uncertainty for each prepare/execute/collect effect response, each owner/case retirement, and both run retirements; repeated causes for the same owner/invocation/stage are accumulated in that bounded record, not appended indefinitely. Evidence-reference arrays and each pending snapshot contain at most effects_total entries; total raw receipt/diagnostic retention still applies. Membership/reconciliation uses maps/sets with O(N log N) work rather than all-pairs scans. Exactly one adapter/session/reader call is active at a time.

### Streamed files and total hashing work

Executable/object/worker/archive artifacts use **streamed** measurement. Vector/input/ledger/observation/receipt parsing retains its existing 8 MiB per-item maximum. Accepted TT01 client sizes recorded in the preparation inputs, 13,836,048 and 15,647,872 bytes, fit the default streamed-artifact cap; they do not justify increasing any parser/vector limit. Source/archive digests never substitute for the executable or object bytes actually measured.

```rust
impl ArtifactMeasurer {
    pub fn new(run_id: RunId, limits: RunLimits) -> Result<Self, BindingError>;
    pub fn measure(&mut self, expected: &ArtifactBinding, file: &std::fs::File)
        -> Result<MeasuredArtifact, BindingError>;
    pub fn usage(&self) -> MeasurementUsage;
}
```

The meter and MeasuredArtifact have no public field constructor, Clone or Deserialize. MeasuredArtifact exposes the exact ArtifactBinding, run_id and measurement-attempt index; a declaration cannot construct it. MeasurementUsage contains `attempts`, `reserved_bytes`, `bytes_returned`, `bytes_hashed`, `read_calls` and optional last InputReadProgress. These are cumulative and never reset after failure. The actual build/vector admission route creates one meter for its run and uses it for every artifact and VectorBundle read; it does not create a fresh meter per file. A custom caller creating unrelated meters has no shared process-wide resource guarantee, and self-reported measurements do not gain generated-build provenance.

Before I/O, validate binding/role, charge one attempt, reserve the full checked `declared_length + 1` against measure_total_bytes, and check declared length against measure_file_bytes (and vector_bytes for retained vector reads). A successful artifact ID cannot be measured again in the same meter; a retry after a failed attempt consumes another full reservation/attempt, never refunds the failed attempt. All actual bytes returned, including the possible EOF sentinel, count toward the usage record; only declared content bytes enter SHA-256. Conservative reservations ensure returned bytes cannot exceed the finite total even after failures. Each actual read call is charged **before** invocation, including EINTR retries; exhausted allowance returns a typed error with exact cumulative progress.

Require a caller-opened regular File; use positional read_at from checked offset zero, at most 65,536 bytes per call, with a **single reusable 65,536-byte buffer** plus fixed hash state. No read_to_end or executable-sized Vec is permitted for streamed roles. Check file type/declared length using metadata before reading; after exactly the declared length, request one sentinel byte at the exact end, require EOF, and check metadata length/type again. At most two metadata calls per attempt are allowed (8,192 total at the hard attempt maximum). Short reads advance the exact returned count; premature EOF, any extra sentinel byte, metadata mismatch, digest mismatch, I/O/read/work exhaustion are failures. No data-dependent whole-file retry, reopening by path or hidden extra hash pass is allowed. The returned artifact stores only binding/progress, not executable bytes. Caller Files/cursors/flags remain unchanged as specified for VectorBundle; errors retain progress and do not imply an atomic snapshot or an interrupted syscall.

The meter's worst-case SHA-256 input is at most measure_total_bytes (hard 4,294,967,296) per admission session, with at most 262,144 reads and 4,096 attempts. The metadata/input parsers have separately finite hash work: RunContract::load hashes its original document once plus each non-overlapping embedded script span once, at most `2 * input_bytes`; the additive catalog-source digest costs at most the unchanged 8,388,608-byte catalog limit once per catalog admission; standalone OperationScript::load hashes at most input_bytes; strict receipt import hashes each retained inline evidence byte at most once, at most receipt_bytes. VectorManifest loading performs no second whole-file hash; VectorBundle streams through the meter while copying validated vector content into its bounded retained buffer. Thus one Rust catalog + one contract + one vector/subject admission + one runner/one receipt import costs at most `measure_total_bytes + 8,388,608 + 2 * input_bytes + receipt_bytes` hashed bytes (hard 4,328,521,728); a separately requested standalone script admission is a separate bounded call. This Rust bound does not silently include a second independent binder/verifier pass. Digest256::of_bytes is a standalone pure utility over caller memory, not a way to bypass the run's meter or claim process-wide accounting. Arbitrary custom hooks/independent library calls remain outside this bound.

The post-build Python binder obeys the same file/total/read/chunk bounds and streams with admitted SHA-256/library hashing. It bounds/parses its three JSON inputs separately. It may hash each input document once, its bounded canonical build-input object once, and its bounded generated measurement manifest once: at most another `5 * input_bytes` hash work, with no hidden whole-artifact rehash. One binder pass followed by the Rust admission/import sequence therefore has a total hard hash-work bound of `2 * measure_total_bytes + 8,388,608 + 7 * input_bytes + receipt_bytes` = 8,665,432,064 bytes. Independent repeated runs/verifier passes are separately budgeted calls, not an unbounded implicit loop. It binds the measured final executable to the actual retained build metadata and the **same** binary executed by the task driver. Passing a digest-looking source label as the executable is rejected; executing a substituted file remains a failed actual-consumer control. Later runtime backends must preserve and use the verified actual object bytes/owner; a TT02 measurement receipt alone cannot guarantee their loading behavior or mint authority.

### Retention and failure accounting

All engine-managed byte allocations/copies reserve retained_bytes before growth, including the fixed read buffer, parsed strings, decoded/serialized copies, contract snapshot, vectors, observations, diagnostics and encoded receipt. Borrowing/shared immutable storage may avoid a counted duplicate; merely holding a second owned copy may not. Byte payloads are bounded to 67,108,864 total, plus bounded fixed hash/record/container overhead under the count limits. This is an explicit payload/cardinality bound, not exact allocator RSS or a hard scheduler/syscall deadline. Custom provider/oracle/adapter allocation is outside the engine-managed bound.

Reserve the mandatory result/cleanup bookkeeping and enough payload space for exact resource IDs/uncertainties/remaining NotRun rows/partial terminal **before** entering effect-capable hooks. Reserve the next observation allowance before execute. If actual planned mandatory records cannot fit the receipt/retention ceilings, refuse the contract intact before effects. Later optional diagnostic overflow preserves stage/length/bounded prefix and an explicit missing-evidence reason; it never drops pending custody or fabricates omitted truth. The retirement schedule above, not a fresh allowance or destructor, handles cancellation and exhausted work. No part of these limits promises interruption of arbitrary custom code or every filesystem syscall.
