## Native ownership, errors and retirement

One invocation has at most seven immutable logical effect registrations:
case-root composite (created directory, IPC/canary/temp subowners), child A,
child B, retained file A, retained file B, inventory-positive child and
inventory-negative child. Inventory children use the third physical child slot
sequentially. Each child composite records its original Child, pidfd, channel,
proc/exec/PID-namespace/mount-namespace handles and native close/reap substate.
A pidfd acquired after Child registration extends that sub-inventory; it never
creates a second registration. Created roots/names are owned only from their
actual original-parent create/open ledger; never from a report's pathname.

Register immediately after actual creation/receipt, before every later fallible
operation. Return each registration exactly once from Prepare/Collect/Retire;
registrations made during advance but not yet returned are discovered by retire.
TT02 retains original InvocationKey, Owner::Fixture and immutable origin. A test
phase may actually reap a child; only an actual retirement report later emits
its exact Pending → Retired transition. Unknown inventory is sticky even if all
known owners later settle. Budget exhaustion without calling a hook is unresolved.

`parent_exit` is an original-pidfd SIGTERM attempt followed by independent pidfd
poll and exact-child WNOWAIT. `parent_reap` uses the original pidfd's exact-child
wait and records actual reap, never wait-any. No message or ACK is requested from
dead A. After reap, capture observes original retained proc outcomes and active B.
Before pidfd acquisition, only the existing exact Child owner can be polled/waited;
there is no PID/PGID kill fallback. Failed signal/wait, missing root proof, timeout
or unexplained ECHILD retains original custody and the error.

Normal unexpected endpoint failure latches the FIRST native failure, seals raw
bytes and stops further normal steps. The adapter returns bounded CaseError
with Unknown cause, not a domain refusal. If Collect is entered, return the
existing typed FixtureError plus new effects; expected-dependent assertions stay
NotJudged. Genuine Cancelled/TimedOut categories remain genuine stops. The
accepted runner may omit Collect after cancellation/deadline or typed adapter
stop; `fixture_failure` may consequently remain None. Never synthesize that
field, callback entry or successful expected-refusal. Retirement seals/exports
the native detail and discovers unreturned effects despite omitted Collect.

Raw publication uses the four fixed reserved slots in schemas.md: early export,
first-failure OR Collect, case-retire, run-retire. Every bytes result is the closed
Snapshot envelope, with full InvocationKey, chronological raw, explicit incomplete
transport, actual hook-entry counts, sticky original-subowner projection and
cumulative charges. Each seal is immutable. A failure wins the shared slot even
when Collect is subsequently entered; later actual hooks update only later seals.
No later seal is fabricated for an uncalled hook. The runner-only deadline route
has no native first failure unless the fixture itself actually stopped.

Each slot owns a separately reserved buffer. Under the private mutation lock,
move that buffer once into a `OnceLock<SealedSnapshot>` after bounded serialization;
release the lock, obtain the slice from `OnceLock::get`, and return it. The slot
never moves/reallocates after publication. A highest-published-slot index uses
release/acquire ordering. `raw_ledger(&self)` may seal the early slot only if no
seal exists, from the cached in-memory state with no native operation; otherwise
it reads an already published slot. After first valid finalization no new early slot can be published; raw_ledger
returns only existing snapshots or None. The driver freezes/writes/hashes current
raw ledgers before ending borrows and finalizing, then may reread existing seals
for byte-identity comparison. No MutexGuard or reference into mutable lock
state escapes, and repeated reads consume no new slot. References remain valid
for their normal Rust lifetime; future `&mut self` hooks/finalize require all
those borrows to end. An endpoint may publish a failure through shared internal
state without changing previously published bytes. No unsafe lifetime extension,
leak, self-reference, raw-slice overwrite or cloned native owner is required.

Retire obeys the actual request's call_id, owner, scope, deadline, remaining
records/bytes and known pending inventory. Runner case and run calls are the only
retry opportunities claimed here; adapter precedes fixture and shares the actual
cumulative allowance. Stop admission; try bounded cooperative close; if necessary
signal only original pidfd; observe actual result and exact reap; retire child
subowners; explicitly close retained Files; remove only created names and the
exact created directory relative to original root owners. Export primary and
subsidiary failures together. Native counters do not reset at retirement. Cleanup uses the actual request
deadline and remaining cumulative allowance; expiration of the normal execution
deadline does not veto cleanup that request still permits.

**Linux close/EINTR:** moving an OwnedFd into the single explicit close consumes
that descriptor owner even when close returns EINTR. Record
`ConsumedWithCleanupError`, errno and origin; never retry the bare FD number or
let a second Drop close a reused descriptor. The physically consumed subowner
can be marked absent; its cleanup error remains in retirement diagnostics/raw
evidence and fails the clean-shutdown gate. A composite becomes Retired only
when all its remaining native owners/created names are actually absent or reaped;
retirement does not erase the consumed-close error. Other Linux close errors also consume the passed owner and retain their exact
cleanup error; EBADF for an allegedly live owned descriptor additionally marks
an inventory violation. No error permits retry or reacquisition by bare number.

After every normal runner return (Ok or Err), end all access/resource/raw
borrows and call `finalize` on the same original session. Its separate immutable
OuterReport cannot alter old snapshots, effects, RunReport bytes or resource
leases. Exact one-shot semantics and constructor-error asset-guard route follow
below and in schemas.md. No panic/abort/destructor-success guarantee follows.
Unresolved originals remain in that session. Drop only transfers its unresolved
state plus reserved terminal storage into the failed-shutdown anchor, with no
hidden signal/wait or cleanup success. This consumes capacity; there is no
aggregate bound across arbitrarily many leaked/new sessions. No report can
reconstruct authority or release a lease.

### Admission assets, finalizer and the no-Prepare boundary

The original root and image A/B Files are three retained admission assets, not
fabricated per-invocation effects for an unentered InvocationKey. Each actually
created case directory has its own case-root registration. Actual run retirement
may close shared admission assets only when dependencies settle; outer cleanup
never closes a consumed owner again.

`finalize(&mut self, budget)` first returns a previously sealed report if one
exists, ignoring the new argument and performing zero work. Otherwise its pure
static admission checks enforce checked arithmetic, original session state,
reserved terminal capacity, unexpired deadline with remaining time no greater
than the contract retirement duration, attempts<=16384, records in 1..16384 and
bytes<=1048576 sufficient for that population's terminal report. Attempts may be
zero. An AdmissionError has no cleanup/native effects and leaves the exact
session/owners intact. Its closed schema is in schema-contract.json.

The first statically valid call permanently stops fixture work and latches that
one budget before any native attempt. Actual live creator/context authentication
is its first counted **read-only** campaign work. Failed authentication seals
Ok(Unresolved), exact guard failure/charges and zero cleanup effects. This root-
adopted refinement avoids unbounded native admission retries and makes every
attempt consume the one fixed allowance. Further calls return the sealed report
without refreshing time/attempts/records/bytes or retrying authentication.

The campaign sends zero worker messages and creates no thread, process, FD grant,
normal step or RetireRequest. It uses only original retained pidfds/exact Child
custody, single-owner explicit close, and names actually created relative to the
original parent. Before pidfd exists there is no PID kill fallback. Admission
assets close once after dependencies settle; with zero Prepare there are only
the three supplied-asset closes after read-only context authentication; actual
context-subowner closes are separately counted, so this is not three total FD
closes. Every native attempt needs
a precharged event slot and bytes plus reserved terminal summary. Small valid
allowances may seal Unresolved. Original unresolved owners stay in the same
session; no report, duplicate or numeric FD reconstructs them.

Each explicit close consumes its owner even on EINTR/error, records the native
outcome, and is never retried by raw number. Clean requires all original owners/
created names settled, no cleanup errors and no sticky unknown inventory.
SettledWithCleanupErrors requires settlement with errors retained; Unresolved
covers remaining/unknown owners, unobserved reap, context/budget stops. Unknown
inventory and EBADF violations stay sticky. The full report slot is reserved at
construction as one additional 1048576 bytes; outer attempt/record/byte work is
additional to unreset runner/fixture allowances and is visible in lifetime totals.

Constructor Err is separate: LinuxFixtureAdmissionFailure returns the exact
three supplied Files/paths and contract to the driver's asset guard, plus opaque
LinuxFixtureAdmissionCustody holding all pending creator/context/temp FDs and its
immutable ConstructorLedger. It exposes no raw FD/clone/process authority. The
custody's one-shot mutable finalizer only closes those actual original auxiliary
FDs; no child/signal/wait/path removal/namespace operation/reopening or complete
creator guard is needed to relinquish them. First valid budget fixes one additional
allowance; repeats return the same immutable admission report. Unattempted owners
stay in that custody. Driver separately closes the actual supplied Files and
combines both reports; no report reconstructs an owner. No successful session,
fixture retirement or silent fallible Drop is claimed.

The already reserved 1MiB slot moves exclusively to success-session OR failure-
custody. Failure uses <=524288 immutable constructor-ledger bytes and <=524288
admission-cleanup bytes; it never allocates a second outer slot. Empty failure
before allocation can use the fixed16384-byte inline empty-ledger/report path;
no auxiliary FD may be acquired before full reservation. The metadata arithmetic
