# ScopeBase execution setup specification

The user requested preparation of the development workflow and has now activated M0–M6 implementation, preserving/porting existing fixes, allowing justified API/architecture improvements and independently tested missing components, with appropriate CI/CD and privileged real-kernel tests. Product migrations/publication remain later. This tooling implements development coordination; the current 120 library requirements and 86 product tasks remain open (the accepted setup baseline had 119 requirements). The accepted [project specification](2026-10-17-scopebase-design.md) and [master plan](../plans/2026-10-17-scopebase.md) remain authoritative for product behavior. Preparation and model reviews cannot qualify a library or environment.

## Organization and alternatives

Use native Codex agents as the primary workers, with small local helpers for task briefs, isolated worktrees, immutable review packages and resource locks. Muse is an additional read-only reviewer and fast source of hypotheses; Sol/Astra adjudicate its findings. This preserves the existing plan and avoids introducing a daemon or autonomous queue. Running every task through Muse would change the selected primary implementer. A new general orchestration service would add unnecessary lifecycle and recovery contracts.

The model/effort choices in `orchestration/policy.json` are explicit per dispatch. Sol high is the normal implementation choice; xhigh is available for difficult contracts. Fresh Sol max may investigate a hard problem after a recorded escalation, including when Astra consultation did not resolve it. Astra high/xhigh handles architecture and critical review. Luna performs mechanical checks with clear acceptance. Muse uses `muse-spark-1.3`, max effort and Contributor mode on, with at most 32 model steps per invocation. Its review is supplementary and cannot replace a required critical review.

## Exact tool contracts

All helpers use Python standard library and Linux/Git. No global config changes, tool installation, network calls, paid model calls or product implementation occur as a side effect of preparation/doctor. The optional explicit Muse run is the only helper that invokes a model. No helper merges, pushes, publishes, changes donor files or creates a Codex goal.

`bin/scopebase-job` invokes `tools/scopebase_job.py` with subcommands:

- `doctor [--repo PATH]`: validate policy, Git/worktree state, Python/Git/flock and available Muse/Codex versions using local commands; report missing optional tools separately. Product compiler/kernel prerequisites remain selected-task checks.
- `prepare --repo PATH --task ID --job ID --role ROLE --goal-file PATH [--base REF] [--effort EFFORT] [--reason TEXT] [--write-path RELPATH ...]`: controller-only preparation. The goal file is nonempty bounded text authored from the user's actual goal. Default base is HEAD. Return a JSON object naming job/worktree/brief/manifest/dispatch paths. It does not launch a worker.
- `review-package --repo PATH --job ID --head REF`: require HEAD descended from the job's recorded base, record full candidate SHA, commit list/stat/full binary diff, validate both sides of renames, and refuse dirty/untracked source in the job worktree. Store an exclusive immutable package at `job/reviews/FULL_CANDIDATE_SHA/`; a fix commit gets a new package, while the same candidate never overwrites an existing package. Return package path. The controller separately launches a fresh reviewer against those exact bytes.
- `reconcile --repo PATH --job ID --reason TEXT --evidence-file ABSOLUTE_PATH --resources-retired`: explicit controller-only release of administrative writable ownership, after independent review/acceptance or deliberate abandonment and actual resource inspection. A nonempty bounded evidence file and reason are snapshotted. Missing retired-resource assertion, malformed evidence or a duplicate reconciliation refuses. Preserve the original manifest/worktree/artifacts, write a fresh `reconciliation.json` plus evidence snapshot bound to the original manifest hash, and let admission ignore only a structurally valid matching reconciliation. This command does not accept a product task or prove runtime retirement from text. Pending/unresolved resources must keep their claim; the controller cannot use the flag in that state.

IDs are ASCII alphanumeric first, followed by alphanumeric/dot/underscore/hyphen, at most 64 bytes. Write paths are nonempty relative literal file/directory prefixes; absolute paths, `..`, `.`, glob metacharacters and Git/state/worktree internals refuse. Writable jobs require explicit paths. Reviewer roles accept none. Dependencies must be accepted in the product task registry (`DONE`, `COMPLETE` or `ACCEPTED`) before preparing a writable job; readonly analysis can inspect a future task without claiming readiness. Active and failed prepared manifests conservatively retain ownership until the controller explicitly reconciles them; no PID absence or mere timestamp expires a claim.

Each job creates an exclusive private directory under the repository's Git-common root `.scopebase/jobs/ID/` and a registered branch/worktree under `.worktrees/ID`. A controller flock serializes check-and-create, and the existing worktree/branch is never reused. Shared manifests, exports, Cargo lockfiles and profile indexes still have a single integration owner. At most three independent implementation lanes are the initial scheduling cap; actual tool availability may reduce it. Reviewers can use separate detached candidate checkouts or read immutable package plus exact candidate source; they do not edit the implementation checkout.

Job files: `job.json`, `brief.md`, `dispatch.json`, private `tmp/`, `cargo-target/` and `evidence/`. Manifest records `execution_state: PREPARED`, the explicit allowed paths and evidence bindings. It is an administrative record, not qualification evidence. Native dispatch explicitly supplies model, reasoning effort and `fork_turns: none`; Muse dispatch names the guarded wrapper. The brief includes exact Global Constraints and selected task text from the plan. Match exact task IDs across actual `## ID:`, `## Task ID:` and `### ID:` headings, derive section end from the actual heading depth, and reject missing/duplicate matches. Cover all 86 registry entries. It includes links to the full specs, worker rules, output paths and independent acceptance/report requirements. It cannot silently rewrite a specification or mark absent environment cells passing.

`bin/muse-run.sh WORKTREE PROMPTFILE OUTPREFIX [--dry-run] [--max-steps N]` invokes `tools/muse_run.py`. Paths are absolute, prompt is a regular nonempty UTF-8 file of at most 65,536 bytes, output prefix has a private exclusive reservation and may contain spaces. There are no arbitrary extra Muse arguments. Invocation fixes provider meta, requested model `muse-spark-1.3`, max reasoning, Contributor on, workspace and worktree mode off; disables write, shell, web, reminders and user-input tools. Approval mode never keeps the default sandbox rather than using `--yolo`. These controls reduce available operations; Git worktrees and prompts are not OS security boundaries. The wrapper cannot attest that an arbitrary CLI/plugin implements its policy honestly.

Outputs are `.jsonl`, `.err`, `.final.txt`, `.execution.json` plus private TMPDIR, with mode 0600/0700. Existing/symlink artifact targets refuse. Dry-run records planned arguments and does not claim execution. Execution records raw exit status, requested model/effort/contributor mode, CLI version, before/after full SHA, terminal and parsed final report. Refuse dirty tracked/untracked source before launch; check it again after completion and preserve an invalid attempt if it changed. Ignored private review inputs are permitted. Success needs raw exit zero, exactly one `run.terminal.completed` with payload terminal `completed`, nonempty text, unchanged candidate and JSON report `{status: "REVIEW_COMPLETE", reviewed_commit: FULL_SHA, summary: TEXT, findings: [...], concerns: [...]}`. Findings require severity (`critical`, `important`, `minor`, `idea`) and nonempty message. Findings are allowed in a successfully delivered review; acceptance remains the controller's decision. Failed process preserves its nonzero status. Invalid/incomplete evidence returns 3, invalid invocation 64 and lock contention 75. Requested Contributor mode is not evidence of the effective provider tier; record it as unverified unless matching successful runtime provider records establish it.

`bin/scopebase-build [--lock-root ABSOLUTE_PATH] [--resource NAME] [--timeout SECONDS] -- COMMAND ARG...` invokes `tools/build_lock.py`. Default per-user host-wide lock root is `$XDG_RUNTIME_DIR/scopebase-locks` or `~/.cache/scopebase/locks`; create it privately without replacing symlinks. Resource defaults to `build`, one exclusive slot. Acquire `flock` before launching exactly once; preserve exit status including 75 and conventional signal exits. Timeout applies to lock acquisition, not command completion or descendant retirement. Lock descriptors remain inherited by the direct command. All participants must use the same root/resource; this does not coordinate Haskoki's unrelated locks or certify remote guest ownership.

## Reports, testing and continuation

Worker reports include DONE/DONE_WITH_CONCERNS/BLOCKED/NEEDS_CONTEXT, commits, exact commands/results, red/control evidence, decisions, assertion changes requiring a ruling, concerns and resource custody. Only the controller updates acceptance and TODO after independent review and current-candidate affected checks. Real correctness defects cannot be parked as cosmetic feedback. Evidence is preserved across fix rounds and compaction. Muse contributes hypotheses; Sol/Astra resolve them against source, specification and tests.

The setup may be tested with fake external service subprocesses, but reports must label that tier. If a real bounded Muse review is run, record that separately from fake-tool tests and product tests. A missing service/authentication does not prevent native workers from using the prepared files, and does not make Muse integration verified.
