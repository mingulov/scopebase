## Production API and effects

```rust
pub struct ObjectKey<K> { /* private epoch, raw, generation; no layout promise */ }
impl<K> ObjectKey<K> {
    pub fn new(epoch: Epoch, raw: K, generation: u64) -> Self;
    pub fn epoch(&self) -> &Epoch;
    pub fn raw(&self) -> &K;
    pub fn generation(&self) -> u64;
    pub fn next_generation(&self) -> Result<Self, ContractError> where K: Clone;
    pub fn matches(&self, other: &Self) -> bool where K: Eq;
}
pub fn require_generation<K: Eq>(submitted: &ObjectKey<K>, current: &ObjectKey<K>)
    -> Result<(), ContractError>;
```

Construction moves its inputs without K trait bounds. Raw zero, object generation 0, epoch ordinal 0 and supplied generation MAX are valid. From MAX-1, advancement reaches MAX; at MAX it returns ArithmeticOverflow before invoking K::clone. Success retains the same epoch, stores the result of exactly one raw clone and advances object generation. The library does not validate the caller clone's semantic equivalence or roll back its effects. Epoch::successor retains its separate accepted EpochExhausted behavior. There is no implicit generation/epoch conversion, automatic generation issue or ID-space reservation in this API.

Matching requires equality of capture ID, producer ID, epoch ordinal, object generation and complete raw K. Compare the epoch first, generation second, raw third. A detectable epoch/generation mismatch performs zero raw equality calls; otherwise perform exactly one raw PartialEq::eq call. PartialEq exists only for K:PartialEq, Eq only for K:Eq, Clone only for K:Clone. `matches` and `require_generation` perform the same ordered relation without an additional payload comparison. Debug never formats raw K, requires no K:Debug and promises no stable textual representation. Auto Send/Sync follows fields. Add no Default, Ord, Hash, Copy, serde representation, setter, implicit conversion or manual unsafe trait implementation.

The complete raw identity domain belongs in K. ObjectKey adds no SourceRef binding/origin, clock, config era, PID birth, filesystem identity or BTF domain. Callers choose honest capture/producer epochs and payload identities. Two `ObservedIdentity::Unknown` reasons may compare equal as values but never become one shared object key. Keep unknown event observations with their own event IDs; there is no unknown-to-default conversion. Generic construction cannot detect a caller who deliberately supplies an unknown sentinel as K.

Library-owned construction/comparison/advancement performs no syscalls, clock reads, hidden logging or lifecycle effects. Comparison performs fixed-size metadata work plus at most one caller equality; successful advancement performs checked u64 arithmetic plus one raw clone. Caller equality/clone can allocate, block, panic or mutate shared interior state; no byte/time/panic/effect bound or rollback is promised for those callbacks. Library-owned source fields remain in place on error/unwind. A caller's interior payload state may change. Tests catch panics in their harness only; production does not contain them. Count limits in fixtures do not establish retained-byte, peak-memory, OOM, syscall-interruption or retirement bounds.

## Test-only protocols and independent truth

Two separate local adapters use production ObjectKey matching; the independent oracle owns append-only action/fact identities and literal expected retention. It never calls production matches/require/next_generation, model lookup helpers or model-returned expected truth. K stable opaque lifetime IDs survive FIFO compaction; no stored index is identity. M's reader identity-present set and mapping retired ring retain different policies. Unknown records carry event IDs41/42 in the direct vectors; no key is minted. A missing old tombstone gives UnknownContinuity, not proved absence. A bound old key versus a known distinct successor remains Mismatch even if unrelated history evicts.

The exact generated population uses one fixed capture/producer epoch, raw7, pending/live/retired caps 2, operation tokens0/1, lengths 0..6 inclusive and alphabet in this order: Allocate7; SubmitDestroy(token0,raw7); SubmitDestroy(token1,raw7); CompleteDestroy(token0); CompleteDestroy(token1); ProvedRetire7. It contains `sum(6**n,n=0..6)=55,987` scripts and 324,726 replayed actions. Compare every prefix's optional outcome, admitted/refused flags, live key, retired projection, pending binding and continuity; record nonzero reuse, unbound-submit, overlap and eviction populations. Single-raw enumeration does not cover live-cap overflow or every compaction shape; required literal multi-raw, raw8/foreign-epoch, cap 0/cap 1/N+1/three-token vectors and all 17 originals remain separate.

Each immutable journal row has action_index0..5 and one InputObservation fact. Other exact fact kinds are Allocation, ForcedRetirement, SubmissionBinding, CompletionRetirement, ExplicitRetirement, CapacityRefusal and DuplicateTokenRefusal. Each kind occurs at most once in a row; FactId is `(action_index, fact_kind)`. An allocation's stable oracle ID is its allocation action index, scoped to that journal. Allocate7 has at most InputObservation+ForcedRetirement+Allocation; capacity refusal instead records InputObservation+CapacityRefusal and creates no allocation. SubmitDestroy has InputObservation plus exactly one SubmissionBinding, CapacityRefusal or DuplicateTokenRefusal. CompleteDestroy has InputObservation and optionally CompletionRetirement. ProvedRetire7 has InputObservation and optionally ExplicitRetirement. Thus at most 3 facts/action and 18/script; retained implementation tables each have at most 2 entries. This is a finite work/cardinality statement, not a generic payload byte bound.

| Action | Exact local transition | Optional outcome |
|---|---|---|
| Allocate7 | Assign a fresh stable local allocation ID if admitted. A still-live old occupant becomes forced-ambiguous before replacement. Never reuse a retained/evicted ID or evict live to make space. | None on successful allocation; CapacityRefused if live admission is impossible. |
| SubmitDestroy(token) | Duplicate token keeps first binding and records DuplicateTokenRefusal without reading/rebinding current identity. Otherwise refuse full pending table; otherwise park Some(current key) or explicit unbound None. | None on admission or duplicate-token refusal; CapacityRefused only for table capacity. |
| CompleteDestroy(token) | Consume only its own parked record. Bound/current full match retires that allocation once. Bound-but-replaced/absent is stale; unbound cannot acquire a current identity. | Matched only for one proved current retirement; Mismatch for bound stale; UnknownContinuity for unbound or missing pending. |
| ProvedRetire7 | Explicit scripted proof names the current fixture allocation; no timestamp/absence inference. No current occupant creates no retirement fact. | Matched for current retirement; UnknownContinuity if no current occupant. |

Local records also retain known/unbound-at-submit, bound-stale versus colliding/unbound, proved versus forced-ambiguous boundary, duplicate-token flag, and creation-observed versus scripted first-seen uncertainty. They are not public error variants. Scripted first-seen admission records creation-unobserved once before config effects, while a known local observation key can still be retained. A later config cannot make creation proved or increment that boundary count again. In M's retired-cap 0 literal, keep active capacity sufficient for valid setup: retain0 tombstones, fabricate no eviction count, and report unknown continuity after retirement. K's whole-cap 0 model instead refuses all pending/live admissions. These are separate local policies.
