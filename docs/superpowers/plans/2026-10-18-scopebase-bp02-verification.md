## Independent fixtures and ordinary tests

Package path `tests/fixtures/bp02/` contains checked-in JSON/binary vectors, provenance, expected results and a standard-library Python generator. It uses Python arbitrary-precision integers and explicit byte offsets/set enumeration, never ScopeBase's parser/geometry/encoder to create expected answers. The generator's `--check` mode regenerates in memory and compares shipped bytes. Private preparation `/home/user/src/m/bpfscope/.scopebase/controller/bp02-preparation-20261018/fixtures/manifest.json` freezes the exact 65-byte BTF and 176-byte two-lane WHO vectors; copy them with their Apache provenance into the package and preserve their SHA256 values. Tests consume these bytes and also retain literal expected values so a shared generator bug cannot silently rewrite every oracle. WHO vectors are 88 bytes per lane, little-endian, with distinct lane values and frozen expected decoded/folded reports.

`tests/support/native_fixture.rs` is a separate test-only syscall fixture; it must not call production metadata/geometry/topology to create expected native map data. It parses actual possible IDs independently into a bounded bitset, refuses >65,536 lanes, allocates a conservative full backing of 65,536 * the literal admitted stride (8,16,88,120 as applicable), and uses distinct payload bytes for every lane. Real map updates consume only actual kernel lanes. It compares ScopeBase's IDs/count with that independent source observation. Raw fixture operations are reviewed separately; they can create/update maps and load the frozen 65-byte literal BTF image, but never load/attach a BPF program. All created FDs have RAII ownership. No test-only fake topology can enter the production real value syscall.

## Minimum real acceptance denominator

This denominator is selected before resource discovery. It is one actual controller-owned x86_64-unknown-linux-gnu SMP kernel/config/build with >=2 possible IDs and at least one offline lane, genuine usable sysfs/procfs, openat2/statx mount identity, BPF map/BTF creation/query permission, and private mount/PID namespace test capability. One concrete source/build is bound by root before execution (an already owned eligible guest is sufficient; no TT05 provisioner is prerequisite). Root records exact source archive/commit and config/build digest, architecture, observed possible/online bytes, compiler/consumer/library feature tree and fixture/candidate hashes. Selected upstream releases remain choices until acquired/built/booted; this contract does not pretend v6.12 architecture reference qualifies any selected release. Missing any property is BLOCKED_ENVIRONMENT, not grounds to reduce the denominator or call all Linux builds supported.

The generic runtime target/preconditions in [native contract](../specs/2026-10-18-scopebase-bp02-native.md) and this one measured minimum acceptance cell are different sets. A baseline result cannot qualify 5.15.223/6.12.113/7.2.11 collectively. Root can select a concrete build from the preselected releases or an already reviewed owned development build; the receipt names which. This flexibility chooses an actual fixture host, not a changed set of required semantics. Additional exact-release claims require their own measured cells later.

The guest is provisioned with offline capacity in advance, for example CPU hotplug capacity greater than boot-online vCPUs after verifying its actual mask/config. The fixture never offlines a host CPU, changes sysctls/rlimits/credentials, installs a toolchain, or silently creates namespaces. Root owns resource admission. Guest setup/lifecycle can use existing manual owned-resource procedures; no circular BP02->TT05 dependency is introduced.
