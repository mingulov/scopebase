## Recommendation

Extract small host crates with explicit proof obligations and a portable regression corpus first. Highest-value starting points are checked per-CPU topology/buffer sizing, strict BTF parsing primitives, transport frame/drain accounting, and bounded process supervision. Adopt existing `libc`, `goblin`, `serde`/`serde_json` and existing BPF ecosystem support for ordinary mechanics; consider upstream contributions for demonstrated generic object/loader deficiencies before maintaining a second loader framework. Keep crypto probe selection, request/transform state machines, accepted kernel profiles, and benchmark truth equations in KryProbe.

The benefit is primarily Linux observability infrastructure shared across the four projects; a few pieces also serve ordinary Rust subprocess runners, bounded parsers, and evidence-processing tools. No current KryProbe crate is a drop-in cross-project library: `kryprobe-privilege` depends on product core/ABI plus libc, goblin, JSON and hashing (`P/crates/kryprobe-privilege/Cargo.toml:9`), while even the nominal raw BTF parser imports its error from the product resolver (`P/crates/kryprobe-privilege/src/btf.rs:12`).

## Twelve candidate boundaries

### 1. Strict BTF reader plus separately supplied profile validation — extract primitives; retain profiles

`Btf::parse`, bounded `chase_wrappers`, member containment/type-extent checks, and `SplitBtf` routing offer substantial value for kernel-layout consumers. Reject truncated headers/records, overflowed ranges, unknown kinds, cycles, excessive nesting, misalignment, wrong primitive widths and incompatible prototypes. Validate the actual pointee type identity, not merely an equal spelling. Split module BTF must route both type IDs and the concatenated base/module string space correctly. Sources: `P/crates/kryprobe-privilege/src/btf.rs:78`, `:202`, `:1036`, `:1223`, `:1376`; entry points `resolve_aggregate_offsets` and `resolve_lifecycle_offsets` at `P/crates/kryprobe-privilege/src/btf_resolve.rs:424` and `:436`.

Preserve tests for nested refcounts and parent-bound escape (`btf.rs:1966`, `:2088`), rival same-name request types (`:2394`), module string routing (`:2460`), malformed prototypes (`btf_resolve.rs:1601`) and hostile images (`:1628`). The opening comment says “no kcrypto knowledge,” but the file now includes lifecycle/crypto prototype validators; extraction must actually split those methods and move the error type. **Difficulty: medium/high.** General Rust usefulness: bounded binary/type-graph parsing; direct consumer applicability: BPF products needing safe kernel structure reads. Limit: little-endian parser and capped subset, not a universal BTF library or automatic CO-RE compatibility guarantee.

### 2. Possible-CPU topology and exact map buffers — extract early

`possible_cpus`, checked CPU-list parsing and `percpu_buffer_len` enforce `round_up(value_size, 8) * possible_cpus`, including offline CPUs. Never size by online CPUs or silently guess on malformed/missing topology. `map_lookup_bytes` and `map_get_next_key` are unsafe because the kernel API takes no userspace output-buffer length; incorrect ABI size can cause an out-of-bounds kernel copy into the caller's allocation. Sources: `P/crates/kryprobe-privilege/src/mapops.rs:272`, `:317`, `:375`. Fix: **86cac42b4bb03fa88d2263526e46163beea24eb5**.

Carry hostile/overlapping topology, absent source, contradictory counts and offline-CPU sizing tests (`mapops.rs:526`, `:540`, `:579`, `:597`, `:616`). Wrap metadata-validated map descriptors and checked buffers rather than exporting the raw unsafe syscall API as the main abstraction. **Difficulty: low/medium**, Linux/BPF-specific; useful to every project reading per-CPU maps. The WHO 80-to-88-byte ABI change needed a second integration fix for a live lookup stride: **31a1f198077406054b073952719e3a02c294163d**. A struct-size unit test alone did not catch the stale consumer (`W/evidence/kcrypto-20261013-s0/wave-a-report.md:29`).

### 3. Insertion-frozen identity with explicit lane provenance — extract fold/pattern and tests

`VWho.identity_present`, `KWHO_IDENTITY_PRESENT`, and `try_fold_vwho` distinguish real zero-valued identity from kernel-zeroed secondary lanes. Only the successful `BPF_NOEXIST` inserting lane owns the identity; migration updates counts and latest task display fields, never redefines insertion-time UID/cgroup/parent/stack. Missing, conflicting or invalid provenance refuses. Preserve the **88-byte wire layout**, padding and every consumer stride together. Sources: `P/crates/kryprobe-abi/src/kcrypto_agg.rs:508`, `:825`, `:982`; BPF insertion/update rules at `P/crates/bpf-kcrypto/src/bin/kcrypto.rs:1017`, `:1084`, `:1163`. Fix: **8d99023f4c65ca8539bcde2319591383fef5c92a** plus the integration fix above.

Regression cases include migration, migration during identity changes, competing inserts, unrelated stack ID zero, genuine UID/stack zero, and absent/conflicting marker (`P/crates/kryprobe-privilege/tests/kcrypto_who.rs:532`, `:585`, `:637`, `:661`, `:677`; ABI fold tests `kcrypto_agg.rs:1172`). These are model/host tests; their `PcpuWho` producer mirrors BPF and is not a live migration proof (`kcrypto_who.rs:465`). **Difficulty: medium.** Broad value: provenance-bearing aggregation; do not generalize insertion identity into event-time identity. Keep product-specific key and identity fields outside a reusable fold primitive.

### 4. Loss channels that survive the failure they report — extract semantics; keep BPF sites local

`KATTRLOSS` is a preallocated per-program/per-CPU array independent of the identity maps that may become full. Each lane and the final fold cap at 255: this is a nonzero degradation indication, not an exact omitted-event count. It covers designated attribution insert failures without conflating KCTX accounting. Sources: `P/crates/bpf-kcrypto/src/bin/kcrypto.rs:389`, `:792`; `kattrloss_fold` and contract at `P/crates/kryprobe-abi/src/kcrypto_agg.rs:133`, `:154`. Fix: **6c4d335eb57bed2a2a43c9e5a3c2cf8274e23f28**.

Preserve full-map, below-capacity positive control, preexisting loss, repeated saturation, cross-CPU/cross-program folding and distinct KCTX refusal tests (`P/crates/kryprobe-privilege/tests/kcrypto_who.rs:783`, `:835`, `:862`, `:890`, `:919`, `:932`, `:1021`). **Difficulty: medium**, broad telemetry value. Retain independent units and semantics for kernel nonexecution, ring reservation failure, queue overflow, table failure and diagnostic caps; do not expose one “lost” scalar that implies exactness.

### 5. Writer partitioning, admission and terminal snapshot receipts — keep mechanism specific; share proof/test kit

Per-CPU is insufficient for exclusivity: different fexit programs can interleave on the same CPU. ADR-0013 documents shared-slot lost updates in KTOT, KCTLCOUNT and drop counters; **862e4591096a90e4cf6ae36c5187ec5dbfa699b7** partitions them by nine program ordinals (KDROPS: 9 × 8 sites). Same-program guard skips prevent concurrent writers but become separately counted kernel misses. Sources: `P/docs/decisions/ADR-0013.md:13`, `:35`; ordinal ABI `P/crates/kryprobe-abi/src/kcrypto_agg.rs:81`; BPF admission/release `P/crates/bpf-kcrypto/src/bin/kcrypto.rs:815`.

`close_kernel_fence` returns `Quiescent` or `Pending`; all program slots × possible CPU lanes must drain, and timeout never grants a receipt (`P/crates/kryprobe-privilege/src/kcrypto_fence.rs:208`, `:240`, `:250`). Carry scripted lost-update and early-receipt counterexamples, stuck-writer, deadline-boundary and every-lane controls (`:406`, `:534`, `:569`, `:608`, `:627`). Detach is a liveness aid; deferred trampoline retirement can still execute a zombie entrant, which must self-refuse. The proof explicitly assumes x86-64 TSO and does not cover aarch64 (`P/docs/decisions/ADR-0011.md:17`, `:39`). **Difficulty: high.** Do not publish a generic safe “BPF fence” abstraction whose supported architecture or attach mechanism is unspecified.

### 6. Ring frames, bounded drain, and exactly-once integrity — extract transport core

The pure `frame_step` is an unusually clean extraction point: busy/discard/emit, aligned length, producer/consumer bounds and overflow refusal (`P/crates/kryprobe-privilege/src/drain/frame.rs:62`, tests `:86`–`:144`). `DrainThread` owns CLOEXEC duplicates, mmap/epoll resources, a bounded queue and worker completion. Stop must return records consumed after the stop request and honest statistics even after panic (`P/crates/kryprobe-privilege/src/drain.rs:173`, `:386`, `:445`, `:466`). Snapshot tail appending must not double-decode (`P/crates/kryprobe-privilege/src/kcrypto_snapshot.rs:891`).

`IntegritySummary` and restricted `SharedLosses` prevent transport losses from being echoed through every backend; `DriverReport::feed_shared_losses` rejects a second feed, and `session_integrity_checked` rejects a missing feed (`P/crates/kryprobe-core/src/evidence/integrity.rs:9`, `:104`; `P/crates/kryprobe-core/src/backend/driver.rs:269`, `:354`). **Difficulty: medium.** Split generic bounded transport/statistics from product frame/observation types. General Rust usefulness includes background workers and stream ingestion, although mmap ring mechanics remain Linux/BPF-specific.

### 7. Checked session states and driver conformance — adopt vocabulary and tests; keep drivers separate

`SessionController` refuses illegal transitions without changing state; preterminal failure goes through `FailedPartial`, then only `Finalized` (`P/crates/kryprobe-core/src/session.rs:12`, `:59`, `:106`). The deeper reusable asset is ADR-0007's conformance contract: shared decoder/registry, observations, per-backend facts, coverage and exactly-once integrity, with only documented ID/time normalization (`P/docs/decisions/ADR-0007.md:34`, `:134`; `P/crates/kryprobe-cli/tests/driver_conformance.rs:1`).

Batch routing and live sensor/tick/drain/stop ownership are deliberately different. Duplicate-key latest-value reduction also differs from batch append semantics, so fixtures cannot erase that distinction by a normalization trick (`ADR-0007.md:142`). **Difficulty: low** for the state machine, **medium** for reusable conformance support. General Rust value: explicit failure-preserving pipelines. Avoid a generic all-purpose driver framework or forcing all projects to adopt KryProbe's exact nine states.

### 8. Pointer generations, request cookies, and lifecycle provenance — keep product state machine; extract oracles

`TransformTracker` tracks allocation evidence, generations, retirement, first-seen unknown objects and ambiguity; completion after pointer reuse must not retire or reconfigure a new lifetime. Sources: `P/crates/kryprobe-privilege/src/kcrypto_lifecycle/tfm.rs:481`, `:636`, `:799`, `:968`, `:1057`. Tests distinguish proven retirement from allocation while still live, destroy/config completion after reuse, dangling entries and bounded capacity (`P/crates/kryprobe-privilege/tests/kcrypto_tfm_lifecycle.rs:593`, `:613`, `:816`, `:886`, `:1081`, `:1129`). Request tests cover 1,000 storage reuses, nested same storage, CPU migration and submit-time transform lifetime (`P/crates/kryprobe-privilege/tests/kcrypto_requests.rs:163`, `:200`, `:229`, `:375`).

Recent test repairs matter: **e529862ea898ca9918b1b64548505e34bd45f8e2** ties transform completions to allocation-submit edges, rather than accepting convenient aggregate totals. **Difficulty: high** to abstract product behavior; low/medium to share a trace-oracle pattern. These ideas transfer to OpenSSL objects, PKCS#11 handles and allocation lifetimes, but their ownership/reuse semantics differ. A shared timestamp-nearness correlator would lose the crucial invariant.

## Kernel/toolchain and qualification limits to carry forward

- Aggregate and lifecycle profiles have different support boundaries. ADR-0006 keeps aggregate at Linux 6.12+ while request lifecycle requires 7.0+ FSESSION; mere presence of kfunc BTF names on 6.12 does not prove attach support. Preserve a real negative kernel lane, not just a version-string gate (`P/docs/decisions/ADR-0006.md:20`, `:36`). The D2 oracle was repaired with explicit old-kernel behavior at **d96fa8c62d3acd87e55aa55cd22b61b8a2e0ca84**.
- Host Rust is edition 2024/MSRV 1.98 in manifest metadata; BPF uses separately excluded crates and lockfiles with nightly-2026-09-16, aya-ebpf =0.2.1, documented bpf-linker 0.10.4 (`P/Cargo.toml:2`, `:15`; `P/docs/dependencies/pins.md:9`). These are inspected project pins, not claims of today's latest or installed tool versions.
- ADR-0009 abandoned the originally proposed atomic-RMW mechanism because the pinned BPF target did not expose the required Rust atomic methods; ADR-0013 subsequently corrected the shared-per-CPU-lane assumption. A host atomic twin is not proof of plain-load/store BPF semantics (`P/docs/decisions/ADR-0009.md:14`; `P/docs/decisions/ADR-0013.md:22`).
- Historical review readiness is not current qualification. The 2026-10-13 review reported static bugs; later source commits implement fixes. Wave records explicitly carry unrun live migration/full-map/bring-up controls (`W/evidence/kcrypto-20261013-s0/wave-b-report.md:48`, `wave-c-report.md:33`, `wave-d-report.md:75`). Those records alone cannot establish whether all later live follow-ups closed; this study did not audit every later sealed receipt. Treat live behavior as unqualified by this study, not as a claim that no later test exists.
- The active selftest-lane task allows fully accounted exit-3 partials only through strict checks and remains under iterative review (`W/tasks/active/kcrypto-20261016-selftest-lane-policy.md:3`, `W/handoff.md:60`). Sharing a lax exit-code adapter would erase the work here. Adopt the mature strict-operand patterns first; reassess the moving AST guard separately after acceptance.

## Extraction acceptance and provenance

A first shared package should carry source SHAs, bug-triggering fixtures, positive controls, original failing behavior, wire sizes, architectural assumptions and the boundaries of each oracle. Required cross-project acceptance: (1) hostile topology refuses before syscall; (2) per-CPU migration preserves provenance; (3) full diagnostic producer maps cannot silence loss; (4) every writer slot drains or remains pending; (5) stop tails are consumed once with honest statistics; (6) malformed replay cannot manufacture a clean or verified result; (7) wrong kernel/BTF profile refuses; (8) helper timeout/ownership loss cannot signal unrelated processes. Host tests cover pure transformations; new compiled BPF artifacts still need pinned old/new-kernel verifier and live positive/negative tests.

License metadata: host workspace/crates and inspected host sources identify **GPL-3.0-or-later** (`P/Cargo.toml:18`, `P/crates/kryprobe-abi/src/lib.rs:1`); BPF manifests/sources identify **GPL-2.0-only** and embed `GPL\0` in the kernel license section (`P/crates/bpf-kcrypto/Cargo.toml:13`, `P/crates/bpf-kcrypto/src/bin/kcrypto.rs:1952`). The ABI header documents intentional GPL-2.0-safe hand-maintained twins rather than importing the host crate into BPF (`P/crates/kryprobe-abi/src/kcrypto_agg.rs:1`). Preserve SPDX/provenance and validate any proposed package's full file/dependency inventory separately; this is metadata reporting, not a legal compatibility conclusion.
