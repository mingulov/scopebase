# Extraction and coverage backlog

Created 2026-10-17 from the feasibility study. These are proposed work items, not implemented library features. No unchecked item is implied complete because a donor once passed a similar test. `Required` means necessary before claiming the stated shared capability; it does not require implementing every optional capability immediately.

Owner roles below identify future responsibilities, not assigned people. Evidence labels and donor pins are in the [overlap matrix](overlap-matrix.md) and repository notes. Concrete test scenarios are `H01`–`H32` in the [test plan](testing-strategy.md). Each selected component owns its applicable subset; unrelated cases remain in the shared corpus and do not block an independent host library. The current [ScopeBase specifications and plans](../../superpowers/plans/2026-10-17-scopebase.md) cover these items. This document preserves the stable research-source IDs; the [root TODO](../../../TODO.md) is the execution ledger, with exact coverage in [traceability](../../superpowers/plans/2026-10-17-scopebase-traceability.json). Package readiness uses two materially different real standalone reference clients. Existing-product migration remains later MG work.

## Work that should not be silently added

- No new universal BPF loader/parser when an upstream dependency plus fixes suffices.
- No universal process/cookie ID that discards birth, exec, namespace, producer domain or image generation.
- No common live driver that erases batch/live or closure-strength differences.
- No promise of old-kernel, Arm, confidential-computing, persistent restart or multi-tool coexistence support without that feature's own evidence.
- No automatic move of private coordination documents, historical logs, raw addresses or broader capture fields into a public library.

## Scheduling and completion rules

Parallel work can own disjoint Linux, capture, BPF, compiler-corpus and documentation files after their interfaces are agreed. Consumer migrations and changes to shared ABI/contracts need one integration owner. Serialize privileged host/VM lanes and any shared generated BPF artifacts; keep per-lane output/toolchain directories.

Close an implementation item only when its exit criterion is met at the selected source version. If an experiment shows no shared library is needed, close the item with the dependency/adapter decision and preserved test case. If a future requirement is missing, add it to root TODO and traceability, with a source item here when needed, naming its invariant, consumer and acceptance test rather than inventing an unscoped utility.
