# Explicit local build-lock routing

CP04's standalone archive audit found that a bare `scopebase-build` invocation did not always select the shared build resource. `tools/build_lock.py` chooses its default from `XDG_RUNTIME_DIR`, then `HOME`. Reconstructed build environments deliberately change `HOME` and omit `XDG_RUNTIME_DIR`; some helpers therefore locked private output directories. TT02 used the real home fallback, a third domain distinct from the controller's runtime-directory lock.

The controller retained existing semantic results with this coordination limitation and paused new local compiler launches. The correction uses the existing explicit `--lock-root` and `--resource` arguments through a frozen private adapter. All subsequent local ScopeBase workers receive the same adapter and resource; packaged helpers still accept an explicit optional wrapper and can run directly outside the repository. No user-specific lock path enters a delivered library or test helper.
