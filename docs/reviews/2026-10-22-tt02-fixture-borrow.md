# TT02 external fixture-access borrowing defect

Date: 2026-10-22. Status: **confirmed usability defect; product repair pending**. This supplements the [accepted engine increment](2026-10-22-tt02-engine.md). It does not claim that TT03 or a native fixture profile is implemented.

`FixtureAccess::new` currently binds the outer slices of `FixtureInput` and `FixtureResource` entries to the same lifetime as their underlying bytes/owners. The constructor copies labels and stores references to those underlying objects in owned vectors. A session preparing local entry arrays therefore cannot return the checked access, even when the real bytes and owners outlive it. A provider with retained arrays works; private field construction used by the vector provider does not demonstrate public constructor usability for this pattern.

An independent external-consumer probe reproduced this on Rust 1.88.0 and 1.98.1, default and no-default. The accepted API rejects the local-array function with E0515 for both arrays; its retained-array twin compiles and runs. An exact private package copy changing only the two outer slice types to `&[FixtureInput<'a>]` and `&[FixtureResource<'a>]` compiles and runs the identical local-array consumer. The inner `'a` borrows remain intact: dying underlying bytes and owners still produce E0515 naming those objects. Successful clients check the actual input and retained owner's pointer/token.

The retained probe has 32 semantic cases: 12 compiled/executed positives and 20 intended compiler refusals, 50 commands and 100 verified log streams. Every Cargo/compiler launch used the explicit controller wrapper and the same admitted twenty-registry-package closure. Setup attempts are recorded separately and do not count as compiler refusal evidence. Results are `.scopebase/controller/resume-20261022/fixture-borrow-probe-r1/results.json`, SHA256 `7df4045424060848e4fef346c0a2afd6b6a101fc3473cc7bbc324e92954c8817`; the private proposed two-line patch is SHA256 `416f6cce65f4c59c357999dc8a9827edf07eb87f2bcf37516ab5b159cd3413a2`.

Product source remains unchanged. After BP02 convergence, root must serialize this constructor-only correction, deliver the local-array positive and underlying-owner refusal controls, run affected source/actual-archive tests and four-client routes, obtain independent review, and record a maintenance acceptance. Existing engine runtime logic, schema and unchanged mutation campaigns need no repeat without a changed input or named gap. TT03 cannot execute its native provider from a packet that works around the defect through leaked arrays, self-reference or unchecked construction. No actual process owner, native probe, kernel or installed route was qualified by this language-level API probe.
