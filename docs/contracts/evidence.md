# Evidence, authority and completion contract

Revision 1, 2026-10-18. Owner: SB01; consumers: all implementation tasks. This record applies the [project specification](../superpowers/specs/2026-10-17-scopebase-design.md), [testing specification](../superpowers/specs/2026-10-17-scopebase-testing-design.md) and [shared interfaces](interfaces.md). It defines reporting boundaries; it is not an implementation, result ledger or runtime authority.

## Evidence domains

| Evidence / authority | What it establishes | What it leaves open |
|---|---|---|
| Selected source SHA and file hash | Particular observed source bytes and their intake attribution | Test execution, present availability, authenticity and support |
| Inspected regression symbol/body | A named candidate mechanism or test exists in inspected source | Passing assertion, active trigger, independent truth and complete coverage |
| Retained file descriptor / HeldFile | Authority over its admitted original open object under the API contract | Immutable content, pathname stability, unique mapping identity or native-link retirement |
| pidfd / proc view | The exact process observation/control authority actually admitted by its constructor | Stable exec/mm identity; observation does not grant signaling or reaping |
| Stat/maps/mount observation | A tagged observation in its particular view and interval | Universal physical identity; raw maps keys may collide |
| Retained mapping proof | The object/view/range/method and validity bracket actually admitted | A future mapping, changed process image or foreign namespace |
| BTF type identity | An admitted type within its object/base/module type domain | A same-name rival type, final runtime key/value linkage or loader behavior |
| Neutral or replay document | Validated data with historical/self-reported source and origin | A newly observed live boundary, file/process owner or cleanup receipt |
| Structural intake check | Required metadata, references and ownership agree with declared source inventories | Donor Git verification, legal compatibility, package behavior and runtime qualification |

Retain partial effects and original authority through fallible retirement or explicit unresolved custody. Dropping an owner does not prove native cleanup succeeded. Native close failure, late worker output, successor generation, counter epoch and invalidated proof remain explicit. Preserve independent factual counts even when correlation or a relationship-dependent claim becomes unknown. Different product shutdown protocols do not collapse into a shared completion boolean.

## Qualification tiers and bindings

| Tier | Required form of evidence |
|---|---|
| T0 | Pure logic with independent literals/vectors and sensitive semantic negatives |
| T1 | Explicit schedules/state models with stated modeled limits |
| T2 | Actual emitted/transformed final objects bound to producer/compiler/backend inputs |
| T3 | Real Linux host operations and required filesystem/namespace/credential triggers |
| T4 | Isolated live-kernel workloads, active positive/excluded populations, runtime semantics and cleanup |
| T5 | Actual independently installed/downstream consumers over distributed package bytes |

These tiers answer different questions; one does not substitute for another. Model stop behavior is reported as a model. Object loading alone does not prove semantic correctness. Old green results do not qualify changed input bytes. Required Btrfs split/collision, overlay copy-up, namespace mismatch, denial and target-mapping audit cells must produce their actual trigger. Missing fixtures or zero activity remain incomplete.

Bindings include library version/features/backend and consumer build, final object hashes, compiler producer, profile/case/fixture/oracle revisions, preselected required cell/branch/population sets, environment identities and cleanup scope. Select required cases from the advertised profile before environment discovery. Independently generated expected truth and a plausible known-bad control must reach the intended semantic assertion; setup crashes do not prove sensitivity.

## Results and readiness

Keep execution, assertion, capability, coverage, harness validation, cleanup and qualification separate. The [testkit contract](../superpowers/specs/2026-10-17-scopebase-testing-design.md#result-and-verdict-contract) defines qualification precedence: invalid binding/harness is invalid; judged semantic failure is failed; missing required evidence or unresolved required cleanup is incomplete; only the complete required positive-support closure qualifies. Keep underlying failures visible through retries and summaries.

An expected-refusal assertion can pass while support remains denied or unknown. Required SKIP/BLOCKED/NOT_RUN and unresolved cleanup cannot produce qualification. Structural commands report `NOT_EVALUATED`; SB01 source inspection is `NOT_RUN` for production qualification. Optional local-source verification verifies only selected source bytes; it never fabricates T3/T4 behavior.

Specification, implementation, package readiness, SDK/native readiness and product migration are separate completion levels. Two independent useful reference clients must exercise real public paths through distributed builds; two wrappers around one mock do not suffice. MG01–MG05 and publication remain later work, without blocking independently qualified components.

## Bounds and diagnostic custody

Report byte, work, memory, wait and resource bounds separately, including charges on failure. A timeout may leave a blocked syscall, worker, mapping or link pending. Account for outstanding cleanup in the caller-owned domain through Drop and reconstruction; do not refund work or discard resources because data observation succeeded.

Default host libraries remain independent of BPF/native compilers, privilege changes, hidden signals, namespaces, global limits and unsolicited logging. Explicit calibration remains caller controlled but still requires implementation, tests and documentation for every advertised branch. Diagnostics are opt-in and bounded; raw paths/content/addresses/command lines remain sensitive local detail. Digest identity does not establish trusted-host authenticity.
