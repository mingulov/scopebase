# BP03 finite host delivery campaign

`execute.py` consumes reviewed source packages and the actual two `.crate`
archives. It creates no archives and performs no native or privileged probes.
Source review, final root bindings and adequate named storage precede a formal
invocation. The full BP03 task remains planned; this driver only checks the
ratified descriptive host increment.

Required arguments are `--source-bpf`, `--source-testkit`, `--bpf-archive`,
`--testkit-archive`, `--output`, `--config`, `--cargo-home`,
`--build-wrapper`, and exactly two `--toolchain-root` arguments of the form
`1.88.0=ABS_ROOT` and `1.98.1=ABS_ROOT`. All paths must be explicit and absolute.
The output must be fresh and outside the worktree. `--config` is forwarded as
the delivered helper's exact `--cargo-config` binding. No resume, dependency
update, tool discovery, install or network fallback is supported.

The driver reserves 20 testkit cells and 12 BPF cells as `NOT_RUN` before any
Cargo operation. Testkit cells run metadata/target projection, library tests,
each enabled integration target, doc tests and the four retained TT01/TT02
clients (80 distinct client executions). Activated cells additionally reference
24 actual executions of the two delivered BP03 clients. Corresponding BPF cells
reference those same exact combined-client receipts, without duplicating their
execution counts. BPF cells also run inherited host regression targets, the new
capability targets, both new examples and the BPF contract consumer. Inherited
live map targets and examples are not launched by this campaign.

Every library cell and independent client has its own target. Default feature
markers remain raw Cargo features. Isolated testkit/retained-client BPF graphs
and combined direct/adapter graphs are recorded separately. Activated combined
consumers require one actual BPF package ID shared by direct and adapter edges.
Archive/source mapping preserves normalized manifests, original manifests,
archive hashes and every delivered file hash. All supplied source originals
remain unchanged; generated workspace/lock files belong to owned copies.

`controls.py` accepts the same bindings and invokes the shipped BPF and adapter
control implementations for both compilers and input kinds. Semantic controls
must fail the intended assertion with a real executed test binary; compilation
or setup failure is incomplete. Each executed mutation binary is retained and
hashed. The same owned mutation source/target is restored sequentially within
one compiler/feature subject. Compile boundaries and the actual foreign-path
binding negative have separate result kinds. The latter refuses before Cargo,
preserves both same-name/version source copies, then restores the admitted
path and checks a real single-ID metadata graph. A successful colliding two-ID
Cargo graph is not required by this pre-qualification binding check.

The two embedded shipped collectors preserve the accepted TT02 implementation
verbatim and use pre-reserved structured rows based on the CP05 custody repair.
`test_delivery.py` runs actual tiny children through selector/read/write/wait/
close/hash/group/lease faults, setup failure, timeout and numeric log overflow
for both shipped scripts. Its logs/checkpoints remain under `TMPDIR`; those
harness checks qualify process custody only.

All command rows record effective config paths, reconstructed environment,
tool hashes, offline vendor and generated-lock projection, real lease identity,
process group, bounded logs, cleanup and errors. Incomplete rows remain visible.
The fixed campaign receipt cannot pass until all required rows and external
client completion groups pass. Disk space must be checked against all retained
targets, binaries, source copies and evidence before a complete campaign; no
pruning or deletion follows from this driver.

The helpers seal schema 2 static bindings after staging and final workspace
rewrites, before version checks or other children. `required-v2.json` preserves
all 528 fixed obligations and their expected oracles, plus the exact local
selection. Each serial command publishes immutable `reserved`, `collected`
and `complete` events. Nonfinal sidecars contain one source projection, command
or result; parent rows contain validated child receipt references. The full
aggregate is written once to `receipt.json`.

A reservation records the request and null process group at that instant. An
interrupted reserved-only command has unknown execution custody: it cannot pass,
retry automatically or release ownership. The collector's nine returned fields
are attached unchanged and persisted before lease or semantic processing.
Wrapper and publication errors are separate from its reason and cleanup facts.
A failed writer permanently stops dispatch and carries the first complete
in-memory custody through `EvidenceFailure`, even when emergency output fails.

Publication uses exclusive temporary files, file and directory fsync, and
no-replace linking. A visible file after a directory fsync failure has uncertain
durability. Parent acceptance requires the actual successful producer return
and exact validated references; reading `status: PASS` from a file is insufficient.
The final receipt has one publication attempt. Failure permits one bounded
emergency attempt and remains incomplete.

Focused transport tests include actual tiny-child collection faults, compound
writer failures, strict chain/schema adversaries, external interruption with a
separate test-owned retirement supervisor, fixed denominators and finite 1/2/4
command series. The controller's explicit C15 route additionally exercises the
actual common wrapper's acquisition refusal and restored positive. Its sole
`--timeout 0` exception is for that no-product-launch control; ordinary commands
retain `--timeout 1800`. These are development custody checks. They do not admit
full source/archive campaigns or qualify strict response-F.
